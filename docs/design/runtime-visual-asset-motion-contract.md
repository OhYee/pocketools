# Runtime visual asset & motion contract

## TL;DR

- **目的**：把“真实实物抛掷动画、真实骰子滚动并停在结果面、真实抽牌并翻牌、经典塔罗牌面”转换成 Android 与 Web 都能实现、复查和验收的运行时合同。
- **当前资产方案**：硬币使用无货币化语义的生成式双面圆片、独立边缘和程序化落地阴影；D20 使用无固定数字的生成式实体骰体、透视多轴滚动和冻结结果数字；塔罗使用逐张登记的 Rider–Waite–Smith 1909/1910 原始扫描候选及生成式牌背。设计稿仍不作为运行时牌面。
- **架构不变**：随机结果先生成并持久化，随后才进入按压、生成、揭示、完成或减少动态效果；动效层只消费不可变 outcome，不访问随机源、不改变规则、不产生第二个会话。
- **许可状态**：本文件是设计与 QA 合同，不是资产许可批准。当前 84 项本地运行时资源已登记在 [`assets/runtime/asset-manifest.json`](../../assets/runtime/asset-manifest.json)，包含来源、SHA-256、归属和候选许可状态；当前交付是本地候选，不能宣称公共发布许可已闭环。
- **当前实现状态**：【已接入】硬币由正面、反面、边缘和程序化阴影组成；六爻复用三枚硬币实体；D20 由无固定数字实体骰体、多轴透视滚动和冻结点数叠加组成；扑克由生成式牌背、纸张牌面、叠牌和洗牌动画组成；塔罗由牌背、抽取/翻牌动画和 78 张 RWS 牌面组成。缺失资源仍保留稳定 fallback，不重随机。
- **本轮设计增量**：FR-053 增加 `includeMinorArcana` 的 22/78 张牌组选择，FR-054 固定五类玩法页的核心实体、单一主操作、相邻重置、高级选项折叠和结果/解析下置；两项不改变结果先持久化、动画只读 outcome 或许可门禁。

## 背景与问题

当前需求和交互基线已经冻结了统一会话、五态动效、离线、无障碍、减少动态效果和触觉降级；本轮已将“真实物体感”拆成离线资产、关键帧和可观察验收条件。实现证据如下：

- `lib/features/coin/presentation/widgets/coin_primitive.dart` 使用本地正反面、独立边缘层、绕水平线的 `rotateX` 面切换、抛起/落定曲线和程序化阴影。
- `lib/features/dice/presentation/widgets/dice_roll_tile.dart` 使用本地无固定数字骰体、X/Y/Z 组合透视变换、实体落地曲线，并将冻结点数作为唯一停面文字；非 D20 面数明确使用实体数字块 fallback。
- `lib/features/tarot/presentation/widgets/tarot_card_primitive.dart` 使用本地牌背和逐张 RWS 牌面，按 Y 轴翻牌并在逆位完成后旋转 180°。
- `lib/assets/runtime/runtime_asset_manifest.dart` 将稳定塔罗 card ID 映射到本地扫描文件；`assets/runtime/asset-manifest.json` 记录每一项运行时资源及哈希。
- `docs/design/gpt-image-2-manifest.json` 将现有设计图标记为 `runtimeAsset=false`。这些图片只能证明静态层级和分镜意图，不能替代本合同定义的运行时资源。

本合同只补足运行时视觉和动效，不重新定义随机算法、牌组数据、D20 聚合、会话状态、历史、分享、导航或内容解释。

## 目标与非目标

### 目标

- 硬币在单次流程中表现为有厚度、有边缘、有落地阴影的物理圆片，明确经历抛起、空中翻转和落定，并停在冻结的正面或反面。
- D20 在 D20 检定中表现为实体骰体滚动、接触/回弹、减速和停面；停面与冻结的点数一致，不能只把数字淡入结果卡。
- 塔罗表现为从牌堆抽出牌、移动到位置、沿 Y 轴翻到牌面；结果牌面使用经典塔罗图像，正逆位、位置和读屏语义与数据一致。
- 资产离线内置、可追溯、可复现；缺少来源或许可记录时，构建或内容包门禁阻止发布。
- 保留既有五态、减少动态效果、触觉独立开关、中断恢复、屏幕阅读器、键盘和 200% 字体约束。

### 非目标

- 不改变 `RandomSource`、规则版本、算法版本、`SessionRecord`、`ToolModule`、历史或分享协议。
- 不把视觉路径当作第二个随机源；视觉路径的旋转角度、抽牌顺序和粒子均不能决定结果。
- 不引入真实货币、面额、肖像、国家标志、赌场、下注、筹码、奖赏或第三方桌游商标。
- 不用生成式设计图、截图、颜色化二次加工图或来源不明的牌面来满足“经典塔罗图像”。
- 不把“公共领域候选”写成跨司法辖区的法律结论；许可门禁仍由项目负责人和许可复核责任方完成。

## 适用范围与优先级

本合同是以下基线的运行时视觉增量：

- 需求基线中的 FR-050、FR-052、FR-053、FR-054、NFR-015、NFR-016、NFR-018、NFR-019。
- 交互基线中的『统一会话模型』『五态动效合同』『平台反馈与触觉合同』『塔罗揭示』『D20 揭示』『硬币揭示』。
- 设计系统中的 `press`、`generate`、`reveal`、`complete`、`reduced` 时长、缓动、粒子上限和触觉边界。

冲突处理顺序固定为：

1. 结果、会话和随机边界以需求与架构基线为准。
2. 资产来源、尺寸、命名和许可以本合同为准。
3. 通用时间、缓动、减少动态和平台反馈沿用既有 tokens；本合同的工具专属关键帧是对通用 token 的精确化。
4. 现有生成式设计图中的文案、形状、抽象牌面或说明性控制不自动进入产品。

## 保留的架构约束

### 生成、持久化与播放顺序

- 用户激活主动作后，先完成规则校验、一次性随机生成、会话封装和本地持久化。
- 持久化成功之前不播放按压后的物体动画，不触发揭示触觉，不展示任何最终牌名、点数或面值。
- 动画收到的是只读 `outcomeSnapshot`，至少包含会话 ID、规则/算法版本、原始序列、聚合结果、牌 ID/方向或硬币序列。
- 动画不得持有 `RandomSource`、调用领域规则、修改结果集合、重排原始顺序或创建子会话。
- “再来一次”只创建新的草稿/会话；它不是当前动画的重播，也不能从当前牌堆或骰池继续抽取。

### 五态映射

| 展示态 | 数据语义 | 运行时允许的视觉行为 | 完成条件 |
| :--- | :--- | :--- | :--- |
| 按压 | `ready` 内的局部反馈 | 主按钮 `translateY=1 px`、`scale=0.985`；物体不改变结果 | 90 ms 或用户取消按压 |
| 生成 | `generating`，输入锁定 | 只显示中性占位、背面或未解析的实体轮廓；不泄露最终语义 | 结果已持久化且视觉时间线完成 |
| 揭示 | 已持久化的 `generated` | 执行本合同定义的抛掷、滚动、抽牌、翻牌和停面 | 所有目标对象已可见或用户跳过 |
| 完成 | `completed` | 结果、过程、规则摘要和下一步入口收束 | 240 ms 收束完成；结果本身不依赖该回调 |
| 减少动态 | 同一结果的替代渲染 | 只允许透明度变化或立即显示；不旋转、不位移、不缩放、不模糊、不粒子 | 80 ms 或立即显示 |

如果动画回调丢失、页面隐藏、路由离开或应用进入后台，必须取消未触发的视觉/触觉事件，并进入同一冻结结果的完成态；恢复不得重播旧关键帧或补发旧触觉。

## 简化玩法页运行时合同

### 页面层级与主操作

五类玩法页的运行时视觉层级固定为“核心实体、主操作、重置、高级选项、结果、解析”：

- 牌堆、牌面、骰子、硬币、爻线等核心实体位于页面顶部；生成前只使用中性牌背、实体轮廓或未解析状态，不提前读取牌名、点数、方向或面值。
- 核心实体下只有一个随机主操作；“重置”与其相邻但不是随机操作。重置只清理草稿或创建空白草稿，不取熵、不创建完成结果、不启动揭示动画。
- 高级选项默认折叠；展开和收起只改变布局，不调用领域规则、随机源或内容解析。高级选项中的塔罗牌阵、`includeMinorArcana`、逆位、D20 骰池、硬币次数和扑克牌组均在提交前冻结。
- 结果卡、过程详情和可用解析位于核心操作区下方；解析只消费已持久化 outcome，缺失解析时保留结果并显示明确的文字降级。
- 页面刷新、后台、路由离开或恢复时保持上述层级、焦点和同一会话；恢复不得将重置误执行为重抽，也不得用默认配置覆盖已冻结字段。

### 五类核心实体映射

| 工具 | 默认核心实体 | 默认主操作 | 重置语义 |
| :--- | :----------- | :--------- | :------- |
| 塔罗 | 牌堆牌背；完成后显示当前牌面 | “抽一张牌” | 清理单牌草稿或创建新草稿，不改变旧牌序 |
| 六爻 | 三枚硬币与待落位爻线 | “开始起卦” | 清理未完成起卦草稿，不撤销已完成会话 |
| D20 | 中性骰体 | “掷骰” | 清理骰池草稿，不补掷或重算旧骰 |
| 硬币 | 中性单枚硬币 | “抛一次” | 清理当前批次草稿，不改变已完成面值 |
| 扑克 | 牌堆牌背；完成后显示有序牌面 | “洗牌并抽取” | 清理牌组草稿，不从旧牌堆继续抽取 |

简化结构不改变五态合同：重置发生在 `ready`/`completed` 的页面操作层，动画中断仍由同一会话恢复；减少动态只改变视觉属性，不改变页面顺序、结果或解析。

## 运行时资产包

### 目录与文件边界

当前实现目录如下；设计稿仍位于 `docs/design/mockups/`，不会被 Flutter 运行时引用：

```text
assets/runtime/
├── asset-manifest.json
├── coin_heads.png
├── coin_tails.png
├── coin_edge.png
├── d20_blank.png
├── playing_card_back.png
├── tarot_back.png
└── tarot/rider_waite/*.jpg (78 张)
```

运行时代码只能从本地打包资源读取。禁止在动画期间从网络下载图片、向远端请求内容或用远端返回值决定面值/牌面。

### 资产清单

| 资产组 | 数量 | 规范尺寸/格式 | 命名与用途 | 许可/归属要求 |

### 资产 manifest 字段

每一项资产必须具备以下字段；缺字段、SHA 不匹配或状态不是 `approved` 时，内容包不能发布：

| 字段 | 要求 |
| :--- | :--- |
| `assetId` | 全局唯一；与稳定牌 ID 或物体 ID 对齐 |
| `path` | 只允许 `assets/runtime/` 下的相对路径 |
| `kind` | `coinFace`、`coinEdge`、`shadow`、`diceMesh`、`diceFace`、`tarotBack` 或 `tarotFace` |
| `width`、`height`、`format`、`colorSpace` | 与实际二进制一致；塔罗运行时画布必须为 `768 × 1288`、WebP、sRGB |
| `sourceUrl`、`sourceFile`、`sourceRetrievedAt` | 第三方资产必须能回到具体文件页面，不接受只写站点首页 |
| `author`、`attribution`、`license`、`licenseStatus` | 记录作者、归属文字、许可名称和 `candidate`/`approved`/`blocked` 状态 |
| `sourceSha256`、`runtimeSha256` | 分别校验原始下载物和处理后运行时文件 |
| `derivativePolicy` | 说明是否裁切、缩放、压缩、调色或仅做格式转换；经典牌面禁止改变构图 |
| `reviewedBy`、`reviewedAt` | 许可复核责任人和时间；未复核写 `待确认`，不能伪造审批 |

建议的单项结构如下：

```json
  "height": 600,
  "format": "JPEG",
  "colorSpace": "sRGB",

  "sourceFile": "00_Fool.jpg",
  "sourceRetrievedAt": "2026-08-23",
  "author": "Pamela Colman Smith",
  "attribution": "Pamela Colman Smith, Rider–Waite–Smith Tarot, original scan source",
  "license": "Public Domain candidate; jurisdiction and per-file source review required",
  "licenseStatus": "candidate",
  "derivativePolicy": "aspect-preserving resize and WebP conversion only",
  "sourceSha256": "recorded in assets/runtime/asset-manifest.json",
  "runtimeSha256": "recorded in assets/runtime/asset-manifest.json",
  "reviewedBy": "待许可复核",
```

### 经典塔罗来源门禁

- 经典牌面候选采用 Rider–Waite–Smith 1909/1910 原始扫描；当前 manifest 为每张本地文件登记具体源文件 URL，并同时记录来源说明文档。公共领域候选不能替代目标地区的逐文件复核。
- 只接受原始扫描或明确允许再分发的版本。分类页已提示部分颜色化版本可能仍受版权保护，因此不得把 AI 修复、重新着色、商业牌组截图或来源不明的高清放大版本混入同一包。
- 归属建议写为“Pamela Colman Smith，Rider–Waite–Smith Tarot，原始扫描来源见逐张链接”；公共领域通常不强制归属，但保留归属有利于审计和下游分发。
- `Public Domain Mark` 是候选许可记录，不替代项目对目标发布地区、扫描版本、商标、隐私和再分发条件的复核。`licenseStatus=approved` 只能由许可责任方写入。
- 当前生成式设计图、`docs/design/mockups/` 图片、`output/imagegen/` 图片和任何 `runtimeAsset=false` 文件不得作为牌面源文件。
- 许可未闭环时，塔罗结果仍可显示稳定文字、牌 ID、方向和“牌面图像暂不可用”；不得显示“已授权”、不得自动换成另一张牌、不得重新抽取。

## 通用动效合同

### 时间与缓动

| 阶段 | 默认时长 | 缓动 | 允许属性 | 禁止属性 |
| :--- | :---: | :--- | :--- | :--- |
| 按压 | `90 ms` | `cubic-bezier(0.2, 0, 0, 1)` | 主按钮位移和缩放 | 物体抛掷、随机、粒子 |
| 生成 | 工具专属；D20/塔罗 `360 ms` | `cubic-bezier(0.4, 0, 0.2, 1)` | 中性占位、牌背、锁定状态 | 最终面值、牌名、方向语义 |
| 揭示 | 工具专属；D20 `640 ms`、硬币单次 `720 ms`、塔罗三牌总长不超过 `960 ms` | `cubic-bezier(0.16, 1, 0.3, 1)` 或物理插值 | 物体变换、阴影、牌面切换 | 新随机值、规则重算、结果重排 |
| 完成 | `240 ms` | `cubic-bezier(0.2, 0, 0, 1)` | `translateY 4→0 px`、`scale 1.02→1`、少量非庆祝粒子 | 爆炸、老虎机、惩罚或庆祝式反馈 |
| 减少动态 | `80 ms` 或立即 | `linear` | `opacity` | `rotate`、`translate`、`scale`、`blur`、粒子 |

所有时长都是视觉上限，不是会话完成条件。状态、焦点、读屏和结果数据不得等待动画结束事件。

### 跳过、中断与恢复

- “跳过动画”只改变展示路径，不改变已保存的 outcome；点击后在最多 `80 ms` 内进入同一完成态。
- 跳过、后台切换、页面隐藏、路由离开和掉帧都不能调用随机源、改变牌/骰/硬币序列或补发触觉。
- 生成状态已经持久化但揭示尚未开始时，恢复直接显示完成结果；生成/持久化未成功时不显示任何随机视觉结果。
- 恢复后的焦点移动到结果标题；屏幕阅读器先播报“已恢复上次结果”，再按 DOM/生成顺序读结果，不逐帧播报。

## 硬币：实体抛掷合同

### 视觉资产与实体规则

- 圆片必须同时具备正面、反面、边缘和动态阴影四层；不能把同一个 `_CoinFace` 复制到两面，也不能用一个平面圆形完成全部旋转。
- 正反面只表达 `heads/tails` 或用户配置的两面语义，不显示货币符号、面额、人物、国徽、国家名称、铸币年份或真实货币纹理。
- 侧视至少能在关键帧中辨认边缘厚度；边缘颜色和光照随水平轴 `rotateX` 改变，不固定粘贴在正面。
- 结果面由冻结的 `CoinSide` 选择，不能由动画结束时的角度反推；目标角度必须显式收束到正面或反面。

### 生成阶段

- 生成阶段沿用现有 `120 ms` 工具时长：显示中性圆片占位或锁定的无标签圆片，输入和会话状态不可变；最终正反面只在揭示阶段进入可读状态。
- 生成阶段不能预先播放抛起或翻转；若页面在此阶段中断，恢复直接进入同一冻结结果，不补播实体动作。

### 单次关键帧

| 时间 | 阶段 | 变换与资产 | 可观察结果 |
| :---: | :--- | :--- | :--- |
| `0～180 ms` | 抛起 | 圆片 `translateY: 0→-48 px`、`scale: 1→0.94`；阴影横向缩小、透明度下降 | 圆片离开落点，边缘开始可见 |
| `180～540 ms` | 空中翻转 | 高点不超过 `-64 px`；目标路径包含绕水平线的 `rotateX: 720° + targetPitch`，`rotateZ` 摆动不超过 `±8°`；使用 `0.0015` 级别透视 | 正反面和边缘交替可见，不能像图标淡变 |
| `540～680 ms` | 下落 | 圆片回到 `-48→0 px`；阴影逐渐恢复；不改变 target side | 速度减小，目标面逐渐稳定 |
| `680～720 ms` | 落定 | 允许一次不超过 `2 px` 的回弹，最终 `translateY=0`、目标面朝向明确 | 720 ms 时面值与 outcome 完全一致 |

完成态在额外 `240 ms` 内收束计数、比例和“再来一次”。单次抛掷必须在 60 fps 录屏中至少出现一次可辨识的边缘视图和一次正反面切换；只看到正面旋转的实现不通过。

### 批量规则

- 批量结果一次性生成并持久化，视觉只按已保存序列揭示。
- `1～10` 次使用多个实体圆片实例或同一实体圆片的明确顺序镜头；每项错峰不超过 `64 ms`，总揭示不超过 `640 ms`，每项仍需有抛起/翻转/落定的缩短路径。
- 超过 10 次不播放 11 个以上长抛掷；可以播放一次代表性实体抛掷，再在 `200 ms` 内展示完整序列、计数和比例。代表性抛掷不得暗示它改变了批量结果。
- 序列、正反面计数和比例只来自 outcome；统计与序列不一致时视为 P0 失败。

## D20：实体滚动与停面合同

### 视觉资产与停面映射

- D20 必须使用本地无固定数字的实体骰体渲染资源，并通过 X/Y/Z 组合透视、落地曲线和透明背景阴影表现滚动；只显示数字的圆角 `Container`、图标或静态结果卡不通过。
- 1～20 的结果标签必须绑定冻结 outcome；当前实现使用同一无数字骰体和稳定结果数字叠加，避免底图数字与结果冲突。未来替换为 mesh 时，面 ID、法线和停面锚点仍必须保持同一适配协议。
- 阴影随高度、接触和最终停面改变；骰体在滚动期间必须出现不同旋转轴和可辨识的实体边界。
- D20 结果池中每一枚骰子都保留生成索引；视觉位置、滚动顺序和布局不得重排原始序列。

### 单枚 D20 关键帧

| 时间 | 阶段 | 变换与可见信息 | 验收要点 |
| :---: | :--- | :--- | :--- |
| `0～96 ms` | 初始冲量 | `translateY: 0→-20 px`；阴影缩小；骰体开始绕至少两个轴转动 | 不是数字淡入；输入和最终摘要保持锁定 |
| `96～432 ms` | 滚动/碰撞 | 至少两次接触式高度变化；绕 X/Y/Z 轴组合滚动；每次反弹不超过 `12 px`；不显示语义性结果播报 | 录屏中能看到不同面和阴影变化，不能只有平面旋转 |
| `432～576 ms` | 减速停面 | 从当前姿态平滑收束到 `face-N` 的法向；最终数字只绑定 outcome 的 `N` | 停面不是由最后随机取值临时决定；原始序号不变 |
| `576～640 ms` | 落稳 | 最多一次 `2 px` 回弹，最终法向和数字稳定 | 640 ms 时停面与 `roll.value` 相等 |

`diceCount=1～6` 时每枚骰子都执行上述实体路径；`diceCount=7～20` 时使用稳定网格并将错峰限制在 `24 ms` 内，总时长仍不超过 `640 ms`。`keepHighest`/`keepLowest` 的“保留/舍弃”标签只能在点数可读后出现，舍弃骰仍须保持 AA 对比度。

D4、D6、D8、D10、D12、D20、D100 快捷面数应沿用同一适配协议；D20 是本合同的 P0 实体验收对象。`2～1000` 的非标准面数不能假装使用不存在的标准多面体，应使用明确标注的“实体滚动数字块” fallback，并仍有滚动、接触、减速和冻结停面；不能退回静态数字卡片。

## 塔罗：真实抽牌与翻牌合同

### 牌组范围选择

- `includeMinorArcana` 默认 `true`，默认牌组为 22 张大阿尔卡那加 56 张小阿尔卡那，共 78 张；关闭时只允许从 22 张大阿尔卡那中抽牌。
- 开关的可见文案为“使用小阿卡纳牌”；开启摘要为“包含 22 张大阿尔卡那和 56 张小阿尔卡那 · 共 78 张”，关闭摘要为“仅使用 22 张大阿尔卡那”。
- `includeMinorArcana` 在会话生成前冻结并写入 outcome/input、历史和分享；切换开关只修改草稿，不修改已完成会话，不请求随机值。
- 关闭时不查找小阿尔卡那牌面资源、不读取小阿尔卡那解释、不改变单牌/三牌阵抽取数量；抽牌顺序和方向仍由冻结 outcome 决定。
- 许可状态独立于开关：manifest 中的 56 张小阿尔卡那必须逐项有来源、归属、哈希和再分发状态；未批准时保留牌 ID/文字结果，隐藏受影响图片并禁用图片分享，不替换牌或重新抽牌。

### 生成与抽牌

- 生成阶段持续 `360 ms`：牌堆保持牌背朝上，允许整体 `translateX=-8→8→0 px` 和 `rotateZ=-2→2→0°` 的一次轻微洗牌；不泄露牌名、牌内图像、方向或牌池计数。牌组范围只在结果摘要和过程详情中展示。
- outcome 已保存后，揭示阶段从牌堆顶部取出对应位置的牌；不能用淡入、凭空出现或只替换抽象几何来代替抽牌。
- 牌的移动顺序必须与 `result.cards` 和位置顺序一致。三牌默认是过去、现在、未来；桌面端可以横向排版，但 DOM 和读屏顺序不变。

### 单张抽取/翻牌关键帧

每张牌的动画上限为 `480 ms`，多张牌错峰 `80 ms`；三牌从第一张开始到最后一张结束不超过 `960 ms`。

| 时间 | 阶段 | 变换与资产 | 验收要点 |
| :---: | :--- | :--- | :--- |
| `0～80 ms` | 离堆 | 顶牌从 `rws1909-back.webp` 牌堆中抬起，z-order 置顶，位移不超过 `8 px` | 视觉上可见“从堆中取出”，不是突然出现 |
| `80～220 ms` | 移位 | 牌沿固定位置移动，`translate` 不超过 `40 px`、`rotateZ` 不超过 `4°`、`scale 0.96→1` | 位置语义不改变；不能重排结果 |
| `220～420 ms` | Y 轴翻牌 | `rotateY: 0→180°`；在约 `90°` 处从牌背切换对应经典牌面；使用透视，禁止只做 opacity | 牌背与牌面两侧都出现，翻转方向稳定 |
| `420～480 ms` | 落位 | `translateY: 4→0 px`，阴影和边框收束 | 牌名、位置和方向与 outcome 一致 |

全牌一次揭示按位置错峰；逐张模式每次用户激活只推进下一张已冻结的牌，不产生新的随机值。用户跳过时立即显示所有已抽牌面，跳过不改变顺序或方向。

### 正逆位与可访问语义

- 牌面图像按原始方向显示；逆位在翻到正面后以 `rotateZ=180°` 和独立“逆位”文字标签表达，不能只依赖图像倒置，也不能把正逆位重新随机。
- 简化塔罗页的语义顺序为牌堆/当前牌面、 “抽一张牌”、 “重置”、 “高级选项”、结果和解析；`includeMinorArcana` 开关必须读出当前值与 22/78 张牌组摘要。
- 生成和未揭示阶段的语义只读“第 N 张牌尚未揭示”，不得提前读出牌名或解释。
- 完成后每张牌的语义名称为“过去位置，隐者，逆位，已揭示”这类 `位置 + 牌名 + 方向 + 状态`；牌面图片为装饰层，屏幕阅读器不需要识别图片文字。
- 经典牌面本身的英文标题、罗马数字或图像不可被 CSS 翻译、重绘或替换；中文显示名和解释继续由现有内容层提供。

## 减少动态效果、触觉与降级

### 减少动态效果

- 系统 `disableAnimations`、应用“减少动态效果”或应用“关闭动画”任一生效时，使用同一已持久化结果，最多 `80 ms` 淡入；关闭动画时立即显示。
- 减少动态路径不执行抛起、翻转、滚动、碰撞、阴影位移、旋转、模糊、错峰或粒子；最终硬币面、骰子停面、塔罗牌面和正逆位必须完全一致。
- 减少动态不改变键盘焦点、读屏播报、结果顺序、会话状态、分享内容或“再来一次”语义。

### 触觉

- 触觉是附加反馈，不能成为真实物理反馈的唯一证据；视觉状态和文字状态必须独立可理解。
- Android 可在会话成功冻结后触发一次 `mediumImpact`，首次揭示/停面/翻牌触发一次 `selectionClick`，完成最多一次 `lightImpact`；不逐枚硬币、不逐骰、不逐张塔罗牌触发。
- Web 只有在用户允许、页面可见、用户激活、能力检测通过且平台策略允许时调用短 `navigator.vibrate`；不支持、拒绝或抛错时静默 no-op。
- 关闭振动与减少动态是两个独立设置；关闭振动不得改变视觉时间线，减少动态不得隐式关闭或增加触觉调用。
- 页面隐藏或流程中断时取消尚未发出的触觉；恢复不补发。

### 资源加载失败

- 运行时资产必须预打包；网络离线不应导致核心随机流程失败。
- 单项图片损坏或 SHA 不匹配时，结果数据仍可恢复和复制；该资产显示稳定的“视觉资产不可用”状态，不重新随机、不替换为未审核来源。
- 小阿尔卡那资源缺失只影响开启 `includeMinorArcana` 时的图片路径；关闭开关时不得尝试加载这些资源，开启时仍保留牌 ID/文字结果并按许可状态禁用图片分享。
- 经典塔罗牌面许可状态不是运行时远端 feature flag；若包内未获批准，构建门禁阻止发布，运行时只作为开发/QA 缺失状态验证。

## 开发交接边界

后续实现可以在不改变领域层和应用壳的前提下替换专属 primitive：

- 硬币：扩展或替换 `CoinPrimitive`，使其消费双面、边缘、程序化阴影和冻结 `CoinSide`；`CoinTosser`、session codec 和统计不变。
- D20：扩展或替换 `DiceRollTile` 为实体骰动画适配器；`DiceRoller` 的原始序列、保留集合、total 和 DC 语义不变。
- 塔罗：扩展或替换 `TarotCardPrimitive`，通过 `TarotCard.id` 查找牌面 manifest，并先按冻结的 `includeMinorArcana` 过滤 22/78 张牌组；`TarotContentCatalog` 继续只负责解释内容，视觉许可元数据单独存放。
- 简化页面：由页面/共享 scaffold 提供唯一主操作、相邻重置和默认折叠高级选项；visual primitive 只消费 outcome，不在“重置”或展开配置时创建领域状态。
- 五态、跳过、恢复和减少动态继续由现有 `AppGenerationStateView`/工具页面的会话流程控制；不要在 primitive 内新建领域状态机。
- 共享按钮、焦点、底栏、错误和读屏继续使用公共组件与 tokens；工具差异只增加专属 visual primitive 和 asset adapter。

- [ ] 系统/应用减少动态、关闭振动、Web 无 `navigator.vibrate`、Android 无触觉能力、屏幕阅读器、键盘和 200% 字体均能完成核心流程。
- [ ] 所有未执行验证均在 QA 报告中标记为“未验证”，不以设计稿 accepted 或静态检查替代运行时证据。
