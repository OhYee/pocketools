# Pocketools v0.1.0 设计系统

- **方向**：克制、精致的现代工具箱；以空间层级、精细排版和可触知反馈建立品质，五工具主题不改变信息架构与组件语义。
- **模式**：浅色、深色、跟随系统；所有可实现值以 [tokens.json](tokens.json) 为机器可读基线。
- **适用范围**：Android 与 Web/PWA 的 v0.1.0 页面和设计稿。
- **设计验收**：G1 交互与视觉设计为【PASS】；Expanded Round-4 revision-2 补齐扑克五态、解释来源边界、历史分享设置和完整 Web 组装证据。
- **边界**：本文定义实现规格，不代表字体、图标、插画或生成式图片已经完成许可审核。

## 参考图运行时落地

用户提供的设计板用于校准日／夜主题、实体舞台、结果层级和动效节奏；它不是运行时图片。当前共享实现通过 `AppSurfaceTokens`、`AppSectionCard`、唯一实体舞台 `AppEntityStateView`、其内部的 `AppGenerationStateView` 状态胶囊和 `AppResultCard` 统一承载这些关系，五个工具只注入语义色和专属 primitive。

- D20 core：移动端 `176 px`、桌面端 `208 px`；结果 tile 继续使用紧凑尺寸；骰池统一放在 `288 px` 的 `AppPhysicalStageSlot` 中，1 枚与 4 枚骰子不会改变舞台高度。
- Tarot core：完成态直接复用 `TarotCardPrimitive` 的 RWS 牌面，资产缺失时保留稳定 fallback 和许可状态。
- Playing cards：牌面固定 `104 × 156 px`（`2:3`），结果使用有序响应式网格和有限抽牌旋转。
- Result surface：raised 结果使用 `24 px` 圆角与内边距、共享阴影和状态 accent；不硬编码 D20 颜色。
- Dark mode：表面、工具主色和 `onPrimary` 与 [tokens.json](tokens.json) 对齐，并通过视觉 QA 验证实际组件对比度。

精确状态、停止条件和剩余差距见 [参考图视觉审计](reference-effect-audit.md)；设计板中的实体图片和彩屑不作为运行时资产。

## 视觉原则

- 应用壳使用中性石墨色与带轻微温度的低饱和表面，避免全局神秘学、游戏化赌场、拟物货币和通用 AI 模板风格。
- 工具主题只覆盖主强调色、弱主题表面和少量图形；导航、排版、间距、状态色和组件结构保持一致。
- 主结果可以有仪式感，但输入、错误、过程、版本和隐私信息必须像可靠工具一样清晰。
- 所有状态同时使用文字、形状或图标表达，不只依赖颜色、旋转、声音或动画。
- 浅色和深色不是简单反相；各自使用独立表面、边框、文字和主题颜色令牌。
- 页面不把每一段内容都包成同规格卡片：一级任务使用空间和排版分组，工具入口、主结果和浮层才使用强调容器，过程明细优先使用分隔线与定义列表。
- 视觉深度只服务于“背景、工作面、抬升面、模态”四层关系；禁止无意义浮空、夸张玻璃、霓虹外发光、廉价双色渐变和大面积噪点。
- 仪式工具仍保持现代产品感：塔罗不使用星盘或传统牌面拼贴，六爻不仿古卷轴，D20 不模仿游戏 HUD，硬币不模拟现金或筹码。

- `主色` 用于主按钮、选中项、关键轮廓和小面积结果强调。

- 深色模式不使用纯黑背景或高亮霓虹描边，避免工具页变成概念艺术界面。

### 色彩使用比例

- 中性背景与表面约占页面可见面积的 `80%～90%`；工具主题弱表面不超过 `16%`，饱和主色不超过 `6%`。
- 同一视口只允许一个实心主按钮；主题辅色只用于短线、微型标记或插图细节，不用于第二个竞争主操作。
- 渐变只允许作为工具图形内部的单色明度过渡，跨度不超过两个相邻色阶、透明度差不超过 `12%`；组件背景、按钮和页面底色使用纯色。
- 深色模式的发光效果上限为 `0`；焦点、选中和层级使用边框、轮廓与明度差表达。

## 字体

### 字体族

- 中文与界面正文：系统无衬线栈，Web 为 `system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Noto Sans CJK SC", sans-serif`。
- 数字和规则表达式：系统等宽栈，Web 为 `ui-monospace, "SFMono-Regular", Consolas, "Liberation Mono", monospace`。
- 不内置未经审核的商业字体；Android 与 Web 使用平台字体时仍需验证字重和行高。
- 牌名、卦名不使用装饰字体，避免影响简体中文识别与 200% 字体适配。

### 字级

| 令牌 | 字号／行高 | 字重 | 用途 |
| :--- | :-------- | :--- | :--- |
| `display` | `40 / 48 px` | 700 | 桌面主结果数字；移动端可降为 `32 / 40 px` |
| `headlineLarge` | `32 / 40 px` | 700 | 桌面页面标题 |
| `headlineMedium` | `28 / 36 px` | 700 | 移动页面标题、结果标题 |
| `titleLarge` | `22 / 30 px` | 650 | 卡片组标题 |
| `titleMedium` | `18 / 26 px` | 650 | 卡片标题、模态标题 |
| `bodyLarge` | `16 / 24 px` | 400 | 正文、输入值、按钮 |
| `bodyMedium` | `14 / 20 px` | 400 | 辅助说明、列表 metadata |
| `labelLarge` | `14 / 20 px` | 650 | 按钮、chip、标签 |
| `labelSmall` | `12 / 16 px` | 600 | 底栏标签、状态标签；不承载长正文 |
| `mono` | `14 / 20 px` | 500 | 骰式、规则版本、原始值 |

- 正文不小于 `14 px`，主要输入和按钮不小于 `16 px`。
- 不固定文本容器高度；200% 字体时允许换行和纵向扩展。
- 数值使用表格数字特性时只影响视觉对齐，不改变屏幕阅读器读法。

## 间距

- 基础网格为 `8 pt`；`4 pt` 只用于图标与短标签的微间距，不用于页面主要分区。
- 可用序列为 `0、4、8、12、16、24、32、40、48、64 px`。
- 页面边距：小屏 `16 px`，平板 `24 px`，桌面 `32 px`。
- 卡片内边距：紧凑 `16 px`，标准 `24 px`；同组字段垂直间距 `16 px`。
- 章节间距：移动 `32 px`，桌面 `40 px`；标题到正文 `8～16 px`。
- 触摸目标最小 `48 × 48 px`，相邻主要操作至少 `8 px`。

## 圆角与边框

| 令牌 | 值 | 用途 |
| :--- | :-: | :--- |
| `none` | `0 px` | 爻线、数据分隔 |
| `sm` | `8 px` | chip、状态标签、紧凑输入 |
| `md` | `12 px` | 按钮、输入、提示条 |
| `lg` | `16 px` | 标准卡片、对话框 |
| `xl` | `24 px` | 结果主卡、底部说明页 |
| `full` | `999 px` | 圆形图标按钮、胶囊标签 |

- 默认边框 `1 px`；焦点环 `2 px` 且与控件外缘留 `2 px` 偏移。
- 选中项优先使用 `2 px` 主题主色边框和弱主题表面，不只改变填充色。
- 爻线、骰子轮廓和硬币示意属于信息图形，最细可见线宽 `2 px`。

## 阴影与层级

| 层级 | 浅色 | 深色 | 用途 |
| :--- | :--- | :--- | :--- |
| `none` | 无 | 无 | 普通列表、嵌套卡 |
| `sm` | `0 1px 2px rgba(20,24,27,0.06), 0 4px 12px rgba(20,24,27,0.04)` | `0 1px 2px rgba(0,0,0,0.32), 0 4px 12px rgba(0,0,0,0.18)` | 悬停、轻提示 |
| `md` | `0 1px 0 rgba(255,255,255,0.80) inset, 0 12px 32px rgba(20,24,27,0.10)` | `0 1px 0 rgba(255,255,255,0.06) inset, 0 14px 36px rgba(0,0,0,0.42)` | 主结果、粘性操作区 |
| `lg` | `0 1px 0 rgba(255,255,255,0.84) inset, 0 24px 64px rgba(20,24,27,0.16)` | `0 1px 0 rgba(255,255,255,0.07) inset, 0 28px 72px rgba(0,0,0,0.56)` | 模态、底部说明页 |

- 页面层级主要依赖表面、边框和间距；阴影只表示浮层关系，不用于每张工具卡。
- 深色模式同时保留边框，不能只靠阴影区分相邻深色表面。

### 空间与材料

| 平面 | 背景与边界 | 光影 | 典型内容 |
| :--- | :--------- | :--- | :------- |
| 画布 `canvas` | 页面背景，无边框 | 无 | 页面留白、导航外背景 |
| 工作面 `work` | 一级表面或透明，无阴影 | 可用 `1 px` 分隔 | 表单、历史列表、设置分组 |
| 内凹面 `inset` | 内凹表面加 `1 px` 中性边框 | 无 | 骰池原始骰、过程详情、只读公式 |
| 抬升面 `raised` | 抬升表面加边框 | `md` | `AppResultCard`、粘性操作区 |
| 模态 `overlay` | 抬升表面，背景遮罩 | `lg` | 对话框、分享预览、移动底部页 |

- 表面质感为细腻哑光；若实现纹理，只允许本地程序化单色噪点，像素尺度 `1 px`、不透明度上限 `1.2%`，不得覆盖文字、输入和数据图形。
- 不使用透明玻璃卡；模态背景可使用 `rgba` 遮罩，但内容面保持不透明。低性能或减少动态模式不需要背景模糊。
- 光源统一来自上方偏左；同层组件不能出现互相冲突的高光方向。边缘高光只用于 `raised` 与 `overlay`，高度固定为 `1 px`。
- 分组优先依赖 `32～40 px` 留白、标题和分隔线；只有工具入口、主结果、异常横幅和浮层使用完整卡片轮廓。

## 图标与工具图形

- 使用统一的 `24 px` 圆角线性图标，默认线宽 `2 px`；选中导航可使用同图标实心版本。
- 图标必须来自可审计的统一来源；在来源和许可确认前只作为设计语义，不指定第三方图标库。
- 通用图标：房屋、四宫格、历史时钟、齿轮、返回、更多、收藏、复制、分享、删除、信息、警告。
- 工具图标：塔罗用单张圆角卡牌轮廓；六爻用上下两组爻线；D20 用正二十面体线稿；硬币用带正反分割暗示的圆片；扑克牌用三张错位的抽象标准牌轮廓与小型花色占位。
- 不使用受第三方品牌保护的角色、徽记、牌面、怪物或规则标志。
- 纯装饰图标从语义树隐藏；单独承担操作的图标按钮必须有可见提示或无障碍名称。

## 组件

### 公共组件与单点样式

以下名称是开发与设计共同使用的公共合同。基础视觉只读取共享 token；工具模块只能传入语义 accent、内容、状态和专属 primitive。任何工具内出现复制的公共按钮、步进器、选择器、结果卡、状态视图或导航都视为设计系统违规。

| 公共组件 | 统一负责 | 工具可扩展 | 单点修改证据 |
| :------- | :------- | :--------- | :----------- |
| `AppNavShell` | 三项移动底栏、三项桌面侧栏、断点、安全区、选中/焦点/禁用 | 当前路由、页面内容 | 修改导航 token 后五工具与 fake 模块同步 |
| `AppToolScaffold` | 标题、配置/结果栏、横幅、粘性主操作、恢复布局 | `ToolDescriptor`、配置区、结果区 | 页面 gutter 或栏宽只改 scaffold/token |
| `AppButton` | primary/secondary/tertiary/destructive、按压、忙碌、禁用、焦点 | 标签、图标、语义 accent、回调 | 高度、圆角、字重、边框与状态只改一次 |
| `AppStepper` | 减/输入/加、范围、键盘、长按、错误、大字体 | label、min/max/step、字符串值 | 触摸目标、输入宽度、重复速率全局同步 |
| `AppSegmentedControl` | 互斥选择、方向键、焦点与纵向降级 | 稳定选项 ID、文案、选中值 | 选中边框与弱表面全局同步 |
| `AppEntityStateView` | 唯一实体舞台、实体布局、动画、结果摘要、恢复和读屏边界 | 冻结 outcome、motion/feedback profile、primitive | 不在舞台外复制状态或结果层；reduced-motion 行为全局同步 |
| `AppGenerationStateView` | `AppEntityStateView` 内唯一的状态胶囊、阶段文案和 live region | phase 与状态文案 | 不承载实体、结果或随机源，不成为独立舞台 |
| `AppPhysicalStageSlot` | 固定实体动画的几何槽位 | 高度与实体 child | 不承载结果详情或随机逻辑 |
| `AppRevealDetailsSlot` | 揭示中保持布局并延后最终详情与语义 | 可见条件与详情 child | 不创建第二个结果层 |
| `AppResultCard` | 舞台内的结果摘要、版本、操作槽和错误保留 | 只读摘要 renderer、`ToolVisualPrimitive` | 不提供独立过程层；结果卡表面、间距、标题与状态行全局同步 |
| `AppPhysicalAction` | D20/DND、硬币和六爻的命中区、键盘/鼠标/触摸激活、语义和按压反馈 | 实体 child、`primaryAction`、语义文案 | 不创建第二条随机路径 |
| `AppPhysicalDeck` | 塔罗和扑克的牌堆点击包装；每次激活只追加一张 | 牌堆 child、单张抽牌动作 | 不把 `n` 当作一次性点击批量动作 |
| `AppDeckResultFlow` | 牌堆固定在前、牌面按抽取顺序追加并响应式换行 | 牌堆和有序牌面列表 | 不重播已有牌或按布局重排 sequence |

公开扩展协议只允许 `ToolSemanticTheme` 与 `ToolVisualPrimitive`，D20/DND、硬币和六爻的实体命中通过 `AppPhysicalAction` 复用，塔罗和扑克的牌堆追加通过 `AppPhysicalDeck` + `AppDeckResultFlow` 复用；所有玩法的唯一实体舞台是 `AppEntityStateView`，其中 `AppGenerationStateView` 仅为状态胶囊。首版 primitive 为塔罗牌、六爻爻线、骰子、硬币、扑克牌；它们不重写公共容器、按钮、表单、结果卡、状态机或导航。基础样式单点调整必须覆盖五工具和仅依赖公开协议的 fake 模块。

### 导航

- `BottomNavigation`：首页、历史、设置三项等宽，移动端固定；选中项同时改变图标、文字和背景，工具入口归入首页。
- `NavigationRail`：桌面 `240 px`，窄态 `88 px`；顺序与移动端一致。
- `PageHeader`：返回、标题、最多两个次操作；200% 字体时次操作进入更多菜单。

### ToolCard

- 内容顺序为主题图标、名称、用途、最近配置、操作。
- 最小高度由内容决定，不固定；移动单列、平板两列、桌面两至四列。
- 默认使用一级表面与中性边框，卡片之间通过不同的抽象工具图形和主题短线区分，不使用同一图标加换色的模板化复制。
- 悬停只抬升 `2 px` 并增加 `sm` 阴影，离开后 `180 ms` 回位；触摸设备无悬停占位，选中或焦点显示清晰轮廓。
- 禁用卡必须展示原因；未上线工具不出现在 v0.1.0 目录。

### IntentField

- 标签始终可见，占位符不替代标签；右侧或下方显示“可选”。
- 标准最小高度 `48 px`，多行备注最小 `96 px`；错误文字位于字段后。
- 隐私提示使用信息图标和短文案，不使用恐吓性红色。
- 字符数或范围限制在接近上限时显示，禁止输入时不清空已有文本。

### RuleSelector

- `SegmentedControl` 用于 2～4 个互斥短选项；D20 的普通、优势、劣势、自定义在移动端可变为两列，文字变长或 200% 字体时转换为纵向单选卡。
- `ChoiceCard` 用于牌阵等需要标题和解释的选择；选中时有边框、勾形和文字状态。
- `StepperField` 包含减、输入、加，三个控件各自满足 `48 px` 触摸目标。
- `StepperField` 的数字输入最小宽 `88 px`；错误时保留输入字符串，范围说明和错误文字占据独立行，不因错误改变相邻字段位置。
- `DiceSidesSelector` 由可换行快捷项 `D4、D6、D8、D10、D12、D20、D100` 和独立“自定义面数”字段组成，不使用无限横向滚动。
- `AggregationSelector` 使用“全部求和、保留最高、保留最低”单选卡；K 只在后两者选中时紧接出现，并用 `aria-describedby` 或平台等价语义绑定当前数量上限。
- `DicePoolSummary` 使用内凹面、等宽表达式和自然语言两层摘要；它只反映配置，不生成或预览骰点。
- `SwitchRow` 整行可点击，开关旁显示当前值和影响说明。
- `Disclosure` 使用“展开／收起”文本与箭头，状态通过 `aria-expanded` 或平台等价语义暴露。

### 主次按钮

- `PrimaryButton`：每个视口同一时刻最多一个主操作；高度至少 `48 px`，使用应用壳或当前工具主色。
- `SecondaryButton`：边框样式，用于调整配置、复制文本等。
- `TertiaryButton`：文字样式，用于取消、了解规则和跳过动画。
- `DestructiveButton`：只在确认上下文中使用错误色，默认焦点不落在最终删除按钮。
- 加载状态保留原按钮宽度，文字改为具体动作，例如“正在生成结果…”，并禁用重复触发。

### 实体舞台与状态胶囊

- `AppEntityStateView` 使用一级表面或工具弱主题表面，统一承载实体、状态、动画和必要结果摘要。
- `AppGenerationStateView` 只作为舞台内的状态胶囊；状态文字与实体视觉属于同一实体舞台，不另建执行层。
- `AppPhysicalStageSlot` 和 `AppRevealDetailsSlot` 是共享的命名布局能力：前者限制实体动画高度，后者在最终详情尚未可见时保持布局稳定。
- D20/DND、硬币和六爻通过 `AppPhysicalAction` 触发主动作；塔罗和扑克通过 `AppPhysicalDeck` + `AppDeckResultFlow` 每次追加一张牌。
- 必须支持“跳过动画”、减少动态和恢复后直接完成三种路径。
- 生成、已生成、揭示三个内部状态使用同一会话 ID，不重建组件触发随机源。

### `AppResultCard` 结果摘要

- 主结果使用 `display` 或 `headlineLarge`；辅助公式使用 `bodyLarge` 或 `mono`。
- 工具弱主题表面只做背景，正文保持中性主文字；成功和失败使用独立状态行。
- 塔罗牌、六爻图、双骰和硬币统计均提供结构化文字等价内容。
- 缺少解释、许可或平台能力时保留主结果，并在舞台内摘要或其下方显示状态提示。
- D20 的 `DiceResultGrid` 展示最多 `20` 枚骰，按生成顺序使用 `#1…#20` 标识；保留与舍弃同时使用文字、轮廓和明度，不改变原始排序。

### 历史与调试详情

- 玩法主体默认不渲染独立过程层；原始结果、规则和版本写入会话、历史与分享载荷，页面只在 `AppEntityStateView` 及必要解析区呈现用户可读结果。
- 展开后按“结构化输入、原始随机值、转换过程、版本与来源”排序。
- 长数据使用卡片或定义列表；移动端和 200% 字体不使用需要双向滚动的表格。
- 原始值使用等宽字体，但允许换行和复制。

### 状态横幅与提示

- `InfoBanner`：离线、规则说明；蓝色信息图标加文字。
- `WarningBanner`：临时会话、许可待审；琥珀图标加文字。
- `ErrorBanner`：随机源、存储、恢复或分享失败；错误图标、原因和恢复动作。
- `InlineError`：紧邻字段，并由字段语义关联。
- toast 只用于“已复制”“备注已保存”等非关键确认，不承载错误恢复。

### 对话框与底部页

- 移动端说明与筛选优先底部页；桌面使用居中对话框，最大宽 `480 px`。
- 标题、影响说明、主次操作顺序固定；关闭后焦点回到触发控件。
- 破坏性确认写明对象、范围和不可恢复性；按钮文案不用模糊的“确定”。

### SharePreview

- 预览卡与字段开关并列或上下布局；预览使用真实最终字段，不用占位私人数据。
- 默认字段为工具、规则摘要、结果和规则版本；问题、备注、精确时间默认关闭。
- 图片能力或许可不可用时禁用图片按钮，并将“复制文本”提升为主操作。
- 生成中只锁导出区域，不锁结果查看和返回。

## 工具专属图形

### 塔罗

- 卡牌比例约 `2:3`，圆角 `12 px`；未获许可前使用抽象几何占位，不绘制具体传统牌面。
- 逆位必须有“逆位”标签；旋转只是附加表现。
- 三牌间距使用 `16 px`，桌面三列等宽，移动和大字体纵向排列。

### 六爻

- 阳爻使用连续线，阴爻使用中断线；每爻旁显示爻位和动静文字。
- 动爻标记使用圆点加“动”字，不能只用绿色或闪烁。
- 本卦与变卦之间使用清晰标题和变更说明，不以箭头代替全部文字。

### D20

- 骰子图形是简化二十面体线稿，中心数字高对比；不模仿任何第三方桌游品牌。
- 优势／劣势的“保留”“舍弃”标签始终可见；舍弃骰仍满足可读对比。
- 达到 DC 使用状态卡而非整页绿色；未达到使用文字和图标，不使用惩罚性震动。

### 硬币

- 硬币使用扁平圆片和有限高光，不使用现金币种、筹码、奖池或博彩桌面元素。
- 正反面用文字或抽象图形区分；自定义标签始终同时保留原始面值说明。
- 批量比例使用条形或圆点计数，并提供数字摘要。
- 单枚 `CoinPrimitive` 使用抛物线高度、边缘压缩与克制高光建立真实感：抛起最高 `64 px`、最多翻转 `720°`、落定回弹不超过 `2 px`；它仍是无面额、无铸币纹理、无厚度夸张的抽象随机标记。

### 扑克牌

- `PlayingCardPrimitive` 使用约 `2:3` 比例、`12 px` 圆角、`2 px` 轮廓与原创/许可明确的抽象标准花色；牌背只使用简洁几何纹理，不复刻第三方牌背。
- 每张结果同时显示 sequence、花色与点数或大小王类型；红黑颜色只是辅助，文字和读屏名称承担必要语义。
- 洗牌只改变中性牌背组的位置和轻微角度；抽牌按冻结 sequence 进入稳定网格。禁止筹码、下注、赔率、现金、荷官、输赢、赌场桌面或中奖反馈。
- 大字体和窄屏改为单列有序卡；桌面可使用多列，但 DOM 与读屏顺序不能因 masonry 或视觉排序改变。

## 触觉与声音

- Android 只使用平台语义 haptics，不自定义长波形：配置选择可用 `selectionClick`；成功提交并冻结结果可用一次 `mediumImpact`；首个揭示或落位可用一次 `selectionClick`；完成最多一次 `lightImpact`。每个工具可省略阶段反馈，不能增加连续震动。
- 塔罗不逐牌、D20 不逐骰、批量硬币不逐枚、扑克不逐张振动；六爻每爻最多一次落位反馈，第六爻完成最多再一次轻反馈。未达到 DC、输入错误、随机源失败和删除确认不使用惩罚性震动。
- Web 仅在用户开启振动、能力检测通过、平台授权或策略允许、页面可见且由用户激活时调用短 vibration：提交建议 `12 ms`、首揭示 `8 ms`、完成 `10 ms`。不支持、拒绝、抛错或能力未暴露时捕获并 no-op，不显示错误、不改变动画或结果。
- “减少动态效果”与“关闭振动”相互独立；前者只限制视觉 transform/blur/particle，后者禁止触觉调用。若平台另有减少触觉偏好则同样 no-op。恢复时不补发中断前未执行的触觉。
- 静态导航、滚动、打开说明、历史查看和普通页面切换不强制震动；错误通过文字、图标、焦点和礼貌／断言式播报表达。
- 声音默认关闭；启用后只允许短、无旋律的确认音，长度上限 `180 ms`、同一会话最多一次，不使用硬币落桌、赌场筹码或胜负音效。

## 动效

### 五态参数

| 状态 | 时长 | Easing | 位移 | 缩放 | 模糊 | 粒子上限 | 目的 |
| :--- | :--: | :----- | :--- | :--- | :--- | :------: | :--- |
| 按压 `press` | `90 ms` | `cubic-bezier(0.2, 0, 0, 1)` | `translateY(0→1 px)` | `1→0.985` | `0 px` | `0` | 确认控件受力，不暗示结果 |
| 生成 `generate` | `360 ms` | `cubic-bezier(0.4, 0, 0.2, 1)` | `translateY(0 px)` | `0.985→1` | `0→0.6→0 px` | `0` | 锁定配置并显示处理状态 |
| 揭示 `reveal` | `640 ms` | `cubic-bezier(0.16, 1, 0.3, 1)` | `translateY(12→0 px)` | `0.96→1` | `8→0 px` | `12` | 展示已经持久化的结果 |
| 完成 `complete` | `240 ms` | `cubic-bezier(0.2, 0, 0, 1)` | `translateY(4→0 px)` | `1.02→1` | `0 px` | `8` | 收束主结果与状态层级 |
| 减少动态 `reduced` | `80 ms` | `linear` | `0 px` | `1` | `0 px` | `0` | 只使用透明度 `0→1` |

- 所有数值是上限而非鼓励填满；无必要时减少位移、模糊和粒子，不增加时长。
- `reveal` 粒子仅限 `2～4 px` 抽象点或短线，总数最多 `12`、生命周期最多 `480 ms`、移动距离最多 `16 px`；完成态最多 `8` 个且不形成彩屑、烟花、金币雨或胜负庆祝。
- 塔罗可在 `reveal` 内附加单轴 `rotateY(0→90→0 deg)`，每张 `480 ms`、错峰 `80 ms`、三牌总时长不超过 `960 ms`；具体牌名与方向在动画前已经冻结。
- 六爻的三枚抽象圆片可各旋转最多 `180 deg`，爻线位移 `8 px`；D20 骰池只允许 `6 deg` 内短摆动。这些变换只作用于抽象图形，不改变结果或读屏内容。
- D20 `7～20` 枚骰使用最多 `24 ms` 错峰，最后一枚必须在 `640 ms` 内可见；批量硬币和完整六爻不逐项延长总时长。

### 五工具 motion profile

| 工具 | generate | reveal | 专属 transform 上限 | haptic 建议时点 |
| :--- | :------: | :-----: | :------------------ | :-------------- |
| 塔罗 | `360 ms` | 单牌 `640 ms`；三牌总长 `960 ms` | 单张 `rotateY 90°`、`480 ms`、错峰 `80 ms` | 冻结提交、全部牌完成；不逐牌 |
| 六爻 | `360 ms` | `640 ms` | 圆片 `180°`、爻线上移 `8 px` | 每爻落位最多一次；第六爻完成可一次 |
| D20 | `360 ms` | `640 ms` | 骰子短摆 `6°`、错峰 `24 ms` | 冻结提交、结果完成；不逐骰 |
| 硬币 | `120 ms` | 单枚 `720 ms`；批量不超过 `640 ms` | `translateY 0→-48→-64→0 px`、绕水平线 `rotateX 720°`、回弹 `2 px` | 冻结提交、落定；批量不逐枚 |
| 扑克牌 | `520 ms` | `640 ms` | 洗牌 `translateX ±8 px`/`rotateZ ±2°`；抽牌 `40 px`/`4°`、错峰 `90 ms` | 冻结提交、首张揭示或完成；不逐张 |

所有 profile 的按压仍为 `90 ms`、完成 `240 ms`、减少动态 `80 ms`。工具 override 只能收窄或在表中明确替代基础时长，不能让动画结束承担随机提交、持久化或结果计算。

### 中断与恢复

- 随机值、规则结果和可恢复会话必须在进入 `reveal` 前完成；生成动画不能直接调用随机源，也不能以动画结束作为提交事务的条件。
- 按压在指针移出、`pointercancel`、失焦或按键释放时立即回到 `1` 倍；取消不会提交。
- 生成中重复点击、重复 `Enter`、双击和多点触摸复用同一提交锁；视觉可以继续，随机请求不得重入。
- “跳过动画”在当前帧取消 `reveal` 与粒子，`80 ms` 内进入同一结果的完成布局；不重新计算、不补发完成触觉。
- 页面隐藏、应用进后台或路由离开时停止视觉时钟。结果已持久化则恢复到完成态；结果尚未完成则恢复原会话的生成状态，不创建新会话。
- 动画被系统或渲染器中断时，以数据状态为准：`generated` 直接渲染完成结果，`generating` 保持忙碌，`blocked` 返回带原输入的错误状态。
- 运行中切换减少动态效果时，取消旋转、位移、缩放、模糊和粒子，使用剩余不超过 `80 ms` 的透明度收束；焦点和读屏播报不重新开始。

| 组件 | 小于 600 px | 600～1023 px | 大于等于 1024 px |
| :--- | :---------- | :----------- | :--------------- |
| 导航 | 底部四项 | 底部四项 | 左侧栏 |
| 工具卡 | 单列 | 两列 | 两至四列 |
| 配置页 | 单列 | 单列或双列 | 配置与摘要双列 |

## 设计交付检查

- 页面只使用本文件与 `tokens.json` 中存在的颜色、间距、圆角、字体和动效值。
- 浅色、深色、离线、错误、禁用、焦点、200% 字体和减少动态均有可实现状态。
- 五工具主题不会覆盖成功、警告和错误语义色。
- 设计稿中的中文保持最少且来自交互文档关键文案，不填入真实私人内容。
- 设计稿不得用廉价渐变、夸张玻璃、模板化同款卡片、神秘学壁纸、游戏 HUD 或博彩反馈代替层级和状态。
- 五个工具的动效分镜都能识别按压、生成、揭示、完成、减少动态五态，并与本文件数值一致；硬币能辨认抛起、翻转、落定，扑克牌能辨认洗牌、抽牌。
- accepted revision-2 `07/08/10c/10d` 与 assembled 只作为交互和视觉设计参考；组件值、可访问性、平台反馈能力和连续响应式行为仍以本文、tokens 与实现测试为准。
- 所有生成式设计证据均为 `runtimeAsset=false`、内部设计参考、待 PM 最终许可复核；G1 设计 PASS 不把设计参考变为运行时资源或发布内容。
