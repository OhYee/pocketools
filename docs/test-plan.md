## `random_core` 测试设计

### 接口与纯度

- 验证 `random_core` 不依赖 Flutter、网络、系统时间、UI 状态或全局随机对象。【计划】
- 验证 `EntropySource.nextBytes(length)` 的长度契约、零长度策略、异常透传和字节消费顺序。【计划】
- 验证 `RandomGenerator.nextInt(maxExclusive)` 的合法范围、`maxExclusive = 1`、非法零值与负值，以及接近实现上限的边界。【计划】
- 验证 `nextBool()` 只消费约定数量的熵并稳定映射二值结果。【计划】
- 验证 `shuffled()` 不修改输入集合、保持元素多重集、长度不变，并在固定向量下给出固定排列。【计划】
- 验证算法版本写入结果，升级算法时保留旧向量和旧会话解释能力。【计划】

### 固定随机向量

每条向量至少包含以下字段：

- 向量 ID、算法版本、字节序约定和原始字节序列。
- 每次熵读取的偏移、长度和预期调用次数。
- `nextInt` 的 `maxExclusive`、被拒绝候选值和最终整数。
- `nextBool`、洗牌或工具规则的预期结构化结果。
- 规则版本、schema 版本以及适用的 Android、Web、纯 Dart 比较范围。

固定向量集覆盖以下情形：

- 全零、全一、递增字节、32 位最大值和跨读取边界的字节序列。【计划】
- D4、D6、D8、D10、D12、D20、D100、`n = 78` 与二值抽样。【计划】
- 第一个候选接受、一个候选拒绝后接受、多个候选拒绝后接受。【计划】
- Fisher–Yates 每个交换位置、恒等排列和非平凡排列。【计划】
- 五类工具的最小、最大和并列结果；扑克覆盖 52/54 张、抽 1 张、抽完整牌组、无放回顺序；Android/Web 比较同一结构化结果。【计划】

### 拒绝采样

对 `limit = 2^32 - (2^32 mod n)` 的实现进行白盒边界验证：

- `x = 0`、`x = limit - 1` 必须被接受，返回值位于 `[0, n)`。【计划】
- `x = limit`、`x = 2^32 - 1` 必须被拒绝并继续读取，不得返回取模结果。【计划】
- `2^32` 可整除 `n` 时不产生多余拒绝；不可整除时仅拒绝尾部区间。【计划】
- 连续拒绝不会递归溢出、截断熵或错误复用同一候选值。【计划】
- 熵源在拒绝后耗尽或抛错时，调用失败且不产出部分随机结果。【计划】
- 通过可观测调用轨迹证明拒绝确实发生，不只比较最终整数。【计划】

### 统计检验

- 在代码中固定样本规模、显著性阈值、分桶方式、自由度和判定规则，参数变更必须经过评审并保留历史记录。【计划】

## 实施交接与待实现挂钩

开发进入测试交接时应一次性提供以下材料：

- 既有 89 条需求 ID 到实现文件、模块、配置、测试与证据入口的映射，以及 FR-053/FR-054 的设计层交接项和明确的未实现项。【计划】
- 扩展 G1 证据包、最新 `gpt-image-2` CLI 生成记录、可验证 4K/high 规格、五工具五态、反馈开关与平台降级路径、design tokens 和旧 built-in 稿排除清单。【计划】
- `random_core` 接口说明、算法版本、固定向量、拒绝采样实现说明与统计任务入口。【计划】
- 五类工具规则版本、FR-047 骰池与扑克表驱动及属性测试入口、64 卦映射来源、塔罗与六爻解释 schema、内容包和许可引用。【计划】
- 会话 schema、旧版本迁移样本、存储适配器和恢复状态图。【计划】
- `ToolModule` 接口、fake 模块示例、统一 session/history/share envelope、依赖规则、共享组件清单、token 覆盖入口和扫描规则。【计划】
- Makefile 11 目标契约、`FLUTTER_BIN` 说明、底层命令映射、本地与 CI 调用关系、`clean` 删除范围和隔离验证方法。【计划】
- 『开发需提供的测试挂钩』中所有挂钩的使用说明与生产隔离证明。【计划】
- Android/Web 精确工具链、可执行命令、支持矩阵、拟发布构建方式和产物定位方式。【计划】
- 日志与分析事件 schema、网络端点清单、权限清单、依赖许可清单和内容资产清单。【计划】
- 已知限制、环境依赖、预期失败和回退步骤；不得以测试人员自行猜测补齐实现契约。【计划】

代码与可执行入口出现后，QA 将独立补充单元、性质、widget、golden、无障碍、integration、平台与构建测试，不以开发自测替代；收到交付后先做追踪完整性和挂钩可用性检查，再执行 L0～L7。【计划】

若实现、命令、环境或证据入口缺失，应记录为对应需求无证据并按优先级进入门禁结论；任何 P0 没有 QA 实际执行证据时阻止发布。【计划】
