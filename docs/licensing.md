# Pocketools 许可与内容边界

- **文档状态**：v0.1.1 本地源码与本地产物候选许可清单；运行时视觉资源已建立逐项 metadata，但候选许可尚未闭环，构建包包含 Flutter 聚合 NOTICE，未生成独立 SPDX/CycloneDX SBOM。
- **版本范围**：Pocketools v0.1.1 视觉运行时资产增量及既有 v0.1.0 内容基线。
- **日期**：2026-08-23。
- **项目许可证**：Apache License 2.0，详见根目录 [LICENSE](../LICENSE)。
- **原则**：不把未核实来源、未知许可或仅供参考的外部内容写成已获授权。

## 适用范围

本文档约束以下内容：

- Pocketools 自有源码、文档、规则实现和原创文案。
- 第三方代码、Flutter/Dart 依赖和生成文件。
- 塔罗牌面、六爻文本、卦象解释、D20 规则引用、字体、图像、图标、音效和设计稿。
- 用户生成的问题、备注、自定义标签和分享载荷。

本文档不是法律意见。目标市场、内容类型或分发渠道发生变化时，项目经理应在发布门禁前重新确认许可和合规要求。

## 项目文件许可

除文件自身包含更具体的版权声明外，Pocketools 贡献者创作的项目源码和项目文档按 Apache-2.0 许可发布。Apache-2.0 的完整文本位于根目录 LICENSE。

贡献者提交内容时应确认：

- 自己拥有提交内容的权利，或有权按项目许可证提交。
- 提交内容没有带入未声明的第三方代码、复制文本、图片、字体、音频或商标。
- 若第三方许可证要求归属、NOTICE、源代码提供或修改说明，已同步提供所需信息。
- 不把用户的私人问题、备注或随机结果写入示例、测试夹具、日志或截图，除非明确脱敏并获得适当授权。

## 第三方代码与依赖

每个正式依赖至少记录以下信息：

| 字段 | 要求 |
| :--- | :--- |
| 包名与版本 | 记录实际使用的稳定版本，不在许可清单中使用模糊范围 |
| 来源 | 记录官方仓库或发布页，不使用无法核实的镜像地址 |
| 许可证 | 记录 SPDX 标识或许可证原名，并确认是否存在附加条款 |
| 用途 | 说明依赖进入哪个平台、模块或发布产物 |
| 归属 | 按许可证要求提供作者、版权和 NOTICE 信息 |
| 审查状态 | 标记已审查、待审查或不适用；待审查项不得进入发布候选 |

开发阶段可以使用工具链临时文件，但它们不应被误认为项目运行时依赖。实际依赖清单应由开发人员在 M2 交付时生成，由测试人员在 M3 复核。

## 内容边界

### 塔罗内容

- v0.1.0 只发布 Pocketools 贡献者为本项目创作的关键词、结构化象征概述、正逆位反思提示和问题，并按 Apache-2.0 许可。
- 牌名、牌组结构和规则数据与具体牌面插画、数字修复图、现代释义、牌阵文章分开审查。
- 不从书籍、网站、课程或其他应用复制现代释义，除非已获得明确许可并完成归属。
- 自有释义应记录作者、版本、审核人和适用的牌面/方向字段。
- 牌面插画必须记录创作者、取得方式、修改状态、再分发范围和归属要求。

### 六爻内容

- v0.1.1 起收录《周易》六十四卦的短篇卦辞原文；古典正文属于公版文本，电子校录以维基文库《周易》分卦页面为工作底本，并使用中国哲学书电子化计划交叉核对。发布前仍需复核电子底本的归属与展示要求。
- 上下卦结构说明、常见结构解读、变化关系和开放式反思提示由 Pocketools 贡献者创作，并按 Apache-2.0 许可。
- 卦象计算规则和现代原创简释与具体译文、注释、排版和数据库分开审查。
- 不把古典文本、现代翻译或他人注释默认视为可自由复制。
- 若使用公版或授权文本，仍需记录来源、版本、适用地域和展示方式。
- 内容只表达文化学习或反思提示，不把许可文本包装成专业判断。

### D20 内容

- 首版优先使用通用骰子、属性/技能检定等描述和原创界面文案。
- v0.1.0 不引入第三方 D&D SRD 正文、角色、怪物、世界观、插画或商标素材。
- 如引用第三方系统参考文档或规则文本，必须记录使用的具体版本、许可、归属和未使用范围。
- 产品名称、图标、商店文案和视觉资产不得暗示获得任何第三方权利方的官方背书。
- 不复制未获许可的角色、怪物、世界观、商标、插画或完整规则百科。

### 生成式和设计资产

交互设计子 agent 使用图像生成能力制作的设计稿或辅助资产，在进入开发或发布前必须记录：

- 资产 ID、页面用途、生成日期和使用的工具或服务。
- 原始提示词、参考图来源和是否存在用户提供素材。
- 是否进行人工编辑、裁剪、合成或二次创作。
- 工具服务条款允许的使用范围，以及商用、再分发和署名结论。
- 当前状态：设计参考、开发占位、待许可复核或允许发布。

本轮生成式运行时资产（硬币正面、反面、边缘、无数字 D20 和塔罗牌背）仅作为本地交付候选，manifest 状态为 `candidate`；在服务条款、商业使用和再分发范围完成复核前，不得宣称可公共发布或作为商店素材。经典 RWS 牌面同样保持 `candidate`，不因“公共领域”字样自动获得跨地区发布资格。

## 归属与 NOTICE

- 需要归属的第三方代码或内容必须在应用的许可与归属页面、发布包或 NOTICE 中按要求展示。
- 归属文本不能被颜色、动画或布局隐藏，且应能从设置或相关内容入口到达。
- 归属信息应包含来源链接、许可证名称、版权方和必要的修改说明。
- 根目录 NOTICE 只记录已经确认的声明；未知或待确认项目不应被虚构填入。

## 用户内容与隐私

- 用户问题、备注、自定义标签和结果不是项目可再发布资产。
- 默认不上传这些内容，不将其用于分析、训练、商店素材或公开案例。
- 分享必须由用户主动发起，并在导出前展示最终字段。
- 测试、截图和缺陷报告使用合成文本；发现真实个人信息时应立即停止扩散并按 SECURITY.md 或维护流程处理。

## 发布前许可门禁

发布负责人需要逐项确认：

- 实际运行时依赖和许可证清单已生成并复核。
- 内容包的文本、图像、字体、图标、音效和归属信息完整。
- 任何 D20 第三方规则引用有明确版本和许可边界。
- 生成式图像和设计稿的使用条款符合目标渠道要求。
- LICENSE、NOTICE、设置中的许可入口和发布包内容一致。
- 未审核、来源不明或不允许再分发的资产已从发布产物移除。
