# 多重占卜模块设计与实现说明

- **文档状态**：【已实现；本地验证通过】
- **版本**：v0.1.1+2 当前增量，规则版本 `multi-divination/1.0.0`
- **更新时间**：2026-08-24
- **目标平台**：Android、Web/PWA
- **适用角色**：项目经理、交互设计、开发、测试、内容维护者
- **权威性**：本文是“多重占卜”模块的功能、规则、交互和实现说明；与历史 v0.1.0 冻结需求发生冲突时，历史需求仍保持不变，本模块的新增行为以本文和源码测试为准。

## 摘要

多重占卜把一副 78 张完整塔罗牌与六爻的六个爻组合在同一次随机过程中：用户每次点击牌堆抽取三张按顺序标记为 A、B、C 的牌，六次点击后共使用 18 张不重复牌。每组三张牌的正位数量映射为一个六爻爻值，六组从初爻到上爻组成卦象；标准模式只使用 A1～A6 作为解释线索，B/C 保留为透明的随机输入，不在 v1 中擅自扩展为独立解释。

模块的核心体验是“一个牌堆、一次点击、一个连续结果”：初始页面只展示牌堆和操作提示；点击牌堆后新增一组三张牌并播放抽牌／翻牌动画；已有牌保持静止；点击 A 牌打开复用的塔罗释义弹层；完成六组后，本卦、动爻、变卦和 A1～A6 摘要直接合并在顶部实体区域，详细解释位于同一页面的下方内容区，不另建动画结果层。

## 来源与内容边界

本模块采用用户提供的两份本地手册作为规则与解释设计输入；原始手册未随仓库分发：

| 来源 | 用途 | 处理方式 |
| :--- | :--- | :--- |
| 本地查询与解释手册 | A1～A6 位置含义、六爻解释顺序、冲突处理和输出边界 | 提炼为 Pocketools 自有结构化内容，不在运行时直接复制长篇原文 |
| 本地操作手册 | 三张一组、六组、正逆位计数、无放回抽取和起卦步骤 | 转换为领域模型、规则函数和可恢复会话格式 |

手册定义的是一种塔罗与六爻的原创融合方法，不应被产品文案表述为传统周易流派的唯一或正统解释。运行时内容位于 `lib/features/multi_divination/content/`，由项目维护者重新组织为短句、结构化标签和风险提示；发布前仍须按 [许可边界](licensing.md) 复核文本、牌面和图像资产。

## 产品目标与非目标

### 目标

- 在一个连续随机会话中建立塔罗牌与六爻的可追溯关联。
- 让用户能看到每一组三张牌如何形成一个爻，而不是只看到最终卦名。
- 允许逐组推进、随时返回和恢复，不因动画重播或页面刷新重新消耗随机值。
- 复用塔罗的牌堆、牌面、翻牌和释义交互，避免为同类牌类工具复制一套页面。
- 将解释明确定位为文化、娱乐和自我反思提示，不制造预测确定性。

### 非目标

- 不实现纳甲、六亲、世应、旬空、神煞或其他完整传统断卦体系。
- 不声称该融合规则具有统计学预测能力、科学验证或传统流派认证。
- 不把 B/C 牌在 v1 中解释成额外的独立未来、建议或结论。
- 不把多重占卜用于医疗、法律、投资、博彩、人身安全或其他高风险决策。
- 不引入联网占卜、账号、云端同步或服务端随机；核心流程保持离线可用。

## 领域规则

### 牌组与抽取

- 使用完整 78 张塔罗牌，包含 22 张大阿卡纳和 56 张小阿卡纳。
- 一次会话开始时对整副牌执行一次 Fisher–Yates 无偏洗牌。
- 每次操作从剩余牌堆取出三张，顺序固定为 A、B、C；六次操作形成六组，共 18 张牌。
- 同一会话不放回、不重复；牌的抽取顺序是结果的一部分。
- 每张牌的正位／逆位独立生成一个二值方向，正位计为 1，逆位计为 0。
- 动画只展示已冻结的牌和方向，不能访问随机源，也不能改变结果。

### 三张牌到一个爻

每组的正位数量为 `u = upright(A) + upright(B) + upright(C)`，映射规则如下：

| 正位数量 `u` | 爻值 | 阴阳 | 动静 | 概率（规则参考） |
| :---: | :---: | :--- | :--- | :---: |
| 0 | 6 | 老阴 | 动，变为阳 | 1/8 |
| 1 | 7 | 少阳 | 静 | 3/8 |
| 2 | 8 | 少阴 | 静 | 3/8 |
| 3 | 9 | 老阳 | 动，变为阴 | 1/8 |

这里的概率是三张独立二值牌方向在理想均匀随机下的组合概率，用于说明规则，不是对真实占卜效果的统计承诺。模块把每组的 `u`、爻值、方向和动爻状态同时保存，便于历史、分享和测试复核。

### 六组到卦象

- 第 1 组是初爻，位于卦的最下方；第 6 组是上爻，位于最上方。
- 六个爻值按初爻到上爻顺序组成主卦。
- 6 变为 7，9 变为 8，静爻保持原值，得到变卦。
- 下卦用于表达内部、基础和近处条件；上卦用于表达外部、环境和后续层次。这是本模块的实用解释框架，不替代传统注疏。
- 未完成六组前不生成伪造的完整卦名；页面只展示当前进度、已完成爻位和已有牌组信息。

### A1～A6 位置语义

标准模式只对每组中的 A 牌提供解释。A 牌的位置与对应爻位一致：

| 牌位 | 对应爻位 | 标准提示主题 |
| :--- | :--- | :--- |
| A1 | 初爻 | 根基、起点、动机、最低条件 |
| A2 | 二爻 | 内部资源、近身关系、可用支持 |
| A3 | 三爻 | 行动、摩擦、门槛、推进代价 |
| A4 | 四爻 | 外部环境、他人、新一层影响 |
| A5 | 五爻 | 核心决策、主导力量、责任位置 |
| A6 | 上爻 | 收束、边界、阶段结果、过度或转折 |

B/C 牌仍显示在组内，作为该爻的随机输入和可追溯证据。后续若增加扩展模式，应新建解释策略和版本，不改变标准模式的结果语义。

### 解释顺序与冲突处理

标准解释按以下优先级组织：

1. 用户问题或意图，以及可选的时间范围。
2. 主卦：当前结构和总体环境。
3. 动爻：发生变化、需要注意的转折位置。
4. 变卦：变化后可观察的结构方向。
5. A1～A6：从基础到收束的六个线索。
6. 动爻对应位置的 A 牌：优先补充当前变化点。
7. B/C：v1 仅保留为随机输入；扩展模式才允许解释。
8. 一致性检查：明确哪些线索互相支持，哪些线索存在张力。

当卦象和塔罗线索不一致时不做多数表决：

- 卦象较顺、塔罗较难：结构条件相对有利，但推进过程有压力或代价。
- 卦象受阻、塔罗较正：整体结构受限，但局部能力、资源或行动窗口仍然存在。
- 无法消解时直接写出“存在张力”和不确定性，不把矛盾强行压成单一结论。

标准完整输出包含：问题／意图、主卦、动爻、变卦、A1～A6 各一句、动爻 A 牌和融合结论。解释文本应保持短句、可扫描，不额外渲染免责声明或内容边界卡片。

## 交互设计

### 入口与页面骨架

- 首页与工具目录合并；注册表新增 `multi_divination`，不增加独立一级导航。
- Android 使用窄屏纵向流；Web 桌面使用左侧栏与右侧主体，主体内容从右侧区域顶部开始，不使用垂直居中来填充空白。
- 页面由共享 `AppToolScaffold`、`AppToolFlowLayout`、`AppEntityStateView` 和共享高级选项容器组成。
- 顶部只有一个实体舞台；不使用第二个“查看过程”、隐藏全高区域或为了动画预留的重复舞台。

### 初始态与抽取

1. 初始状态显示有厚度的塔罗牌堆、规则简短提示和折叠的高级选项。
2. 用户点击牌堆或用键盘激活同一牌堆命中区。
3. 应用先生成并保存一组三张牌，再播放这一组的抽出、横向排布和翻面动画。
4. 动画期间只更新当前新增组；已有组不重新布局、不重新播放、不改变位置。
5. 动画完成后，牌堆仍然可点击；下一次点击追加下一组，直到六组完成。

### 牌面与释义

- 每一组按 A、B、C 顺序显示，牌面使用现有 Tarot card primitive 和经典牌面数据。
- 点击 A 牌打开现有 `TarotInterpretationSheet`，弹层展示牌名、正逆位、关键词、简释和反思问题。
- 点击 B/C 不会触发新的随机过程；可展示“本标准模式中作为随机输入保留”的说明。
- 六组牌在空间不足时自然换行；不通过透明占位、`Offstage` 或独立隐藏容器制造稳定高度。
- 牌组和牌面是同一个底层交互族；塔罗页、扑克牌页和本模块共享牌堆命中、逐张追加和揭示边界。

### 完成态与解析

完成六组后，顶部牌堆实体仍可点击，点击会创建关联的新一轮多重占卜；顶部实体内直接显示：

- 主卦和变卦；
- 动爻位置；
- 六组进度和 A1～A6 的短摘要；
- 继续新一轮的可操作提示。

详细解释、六爻结构和 A1～A6 逐项内容在同一页面的下方内容区展示。它是解释内容区，不是第二个动画舞台；随机结果、状态和主结果不在顶部与下方之间重复生成。

### 高级选项、返回与恢复

- 高级选项默认折叠，v1 只包含问题／意图、规则说明和能力边界。
- 输入框在当前会话完成或部分完成后仍可编辑；已开始的会话继续使用已经冻结的意图，修改后的内容在下一轮新会话生效。
- 重置只清理当前草稿并保留历史，不消耗随机值；完成态点击牌堆直接开始新会话，因此不再额外显示重复的重置操作。
- 页面返回、浏览器后退和系统返回都交给模块上下文；弹层先关闭弹层，工具页再返回上一级。
- 页面刷新、后台恢复或重新打开时从会话仓库恢复牌序、方向、组数和派生卦象，不重新洗牌、不重放历史随机值。

### 动画、触觉与无障碍

- 按压、生成、揭示、完成和减少动态效果沿用全局五态反馈合同。
- 抽牌动画使用局部 `RepaintBoundary` 和共享命名槽位，新增内容不会推动页面下方的高级选项或主体布局。
- 减少动态时跳过位移和翻转，只保留可理解的短透明度变化或立即显示冻结结果。
- Android 按设置提供触觉反馈；Web 和不支持的平台静默降级，不影响随机结果。
- 牌堆、每组三张牌、A 牌释义弹层、进度和卦象都有语义标签、键盘焦点和屏幕阅读器可读状态。

## 技术架构

### 模块分层

```text
lib/features/multi_divination/
├── content/
│   ├── multi_divination_content_catalog.dart
│   └── multi_divination_interpretation.dart
├── domain/
│   ├── multi_divination_models.dart
│   ├── multi_divination_reader.dart
│   └── multi_divination_rules.dart
└── presentation/
    ├── multi_divination_labels.dart
    ├── multi_divination_session_codec.dart
    ├── multi_divination_tool_module.dart
    ├── multi_divination_tool_page.dart
    └── widgets/
        ├── multi_divination_group_view.dart
        └── multi_divination_result_view.dart
```

- `multi_divination_rules.dart`：纯规则函数，负责三张牌计数、爻值和卦象派生。
- `multi_divination_models.dart`：配置、牌位、牌组、读取结果和版本化派生字段。
- `multi_divination_reader.dart`：注入 `RandomSource`，执行一次洗牌和逐组追加。
- `multi_divination_content_catalog.dart`：解释字段和内容元数据。
- `multi_divination_interpretation.dart`：按标准优先级组合 A1～A6、动爻和融合结论。
- `multi_divination_session_codec.dart`：严格校验的持久化与恢复协议。
- `multi_divination_tool_module.dart`：把规则、页面、历史、分享和隐私能力接入统一 `ToolModule` 注册表。
- `multi_divination_tool_page.dart`：只编排共享页面骨架和模块状态，不复制随机规则。
- `widgets/`：逐组三张牌与详细结果的展示组件，使用现有 Tarot primitive 和共享设计 token。

### 随机、会话与恢复

```mermaid
flowchart LR
    Tap[点击牌堆] --> Validate[校验当前配置]
    Validate --> Frozen[冻结本轮配置]
    Frozen --> Reader[MultiDivinationReader]
    Reader --> Shuffle[首次会话一次洗牌]
    Shuffle --> Draw[取三张 A/B/C + 三个方向位]
    Draw --> Save[先写入会话仓库]
    Save --> Animate[局部抽牌与翻牌动画]
    Animate --> Summary[顶部实体摘要]
    Summary --> Interpret[六组完成后组合解释]
```

`MultiDivinationReading.deckOrder` 保存一次洗牌后的完整 78 张稳定牌 ID 顺序。这样做不是为了暴露随机细节，而是为了保证部分草稿恢复、继续抽取和历史重放使用同一牌序：恢复时只消耗后续三张牌的方向随机值，不重新洗牌。会话解码同时校验牌序是否为完整排列、组内是否恰好为 A/B/C、牌是否重复以及派生字段是否与原始输入一致。

会话载荷的核心字段为：

| 字段 | 语义 |
| :--- | :--- |
| `groupCount` | 已完成的组数，范围 0～6 |
| `groups` | 每组三张牌、方向、正位计数和爻值 |
| `deckOrder` | 当前会话的一次性 78 张牌序，用于恢复继续抽取 |
| `complete` | 是否已完成六组 |
| `primaryHexagramId` | 完成态主卦稳定 ID；未完成时为空 |
| `changedHexagramId` | 完成态变卦稳定 ID；未完成时为空 |
| `contentVersion` | 解释内容版本 |

私有 session ID、父 session ID、设备信息和精确时间不进入默认分享预览；公共分享继续通过共享白名单策略过滤。

### 扩展点

新增玩法不应修改页面 shell：

1. 新增独立 `domain`、`content` 和 `presentation` 目录。
2. 实现 `ToolModule`、会话 adapter 和最小 privacy capability。
3. 复用 `AppToolScaffold`、`AppEntityStateView`、`AppPhysicalDeck` 或其他合适的实体 primitive。
4. 在 `DefaultToolRegistry` 注册模块，并补充模块、会话、布局和无障碍架构测试。
5. 仅在新交互确实不同于现有 primitive 时新增共享组件；不要在每个页面复制按钮、牌堆或状态舞台。

本模块未来可以通过新的解释策略支持 B/C 扩展、时间范围或更详细的卦理，但必须保持规则版本和 session codec 向后兼容。

## 风险与发布边界

- **解释误读风险**：页面和分享内容只展示结构化解释字段，不根据输入生成确定性或专业结论。
- **传统性误读风险**：使用“本模块规则”“实用框架”等措辞，不宣称正统流派或科学预测。
- **内容许可风险**：本模块使用结构化原创解释与现有牌面数据；任何新增牌面图像、长篇译文或第三方图表都必须先完成许可审查。
- **恢复一致性风险**：`deckOrder`、原始牌位和派生字段必须同时持久化并通过 codec 校验，不能以默认配置静默覆盖。
- **布局回归风险**：新增组只能在局部内容区域变化；共享 `AppEntityStateView` 的命名槽位是唯一的动画稳定性边界。

本模块当前达到“本地源码与自动化测试交付”状态，不等同于公共 Web 部署、应用商店签名或真实 Android 设备矩阵通过。
