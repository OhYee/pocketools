## 背景与问题

项目已从产品与设计基线进入首版交付收口。当前已有完整 Flutter 源码、共享架构、Makefile、五工具、持久化、Web/PWA 构建与阶段测试证据；最终产物、矩阵和发布报告仍需按真实执行结果固定。以下问题描述本计划建立时的起点及仍需持续防止的回归：

- 没有稳定需求 ID，开发和测试无法逐条追踪。
- 没有交互设计交付物，直接开发会导致关键页面状态、动画、错误处理和无障碍行为反复返工。
- 既有 built-in 图像生成稿质量不满足实现要求，继续沿用会固化低质量视觉和缺失的动效状态。
- 没有开源治理文件，外部贡献者无法理解许可、贡献、安全报告和行为边界。
- 没有第三方和内容许可清单，塔罗、六爻、D20 和视觉资产存在发布风险。

本计划把这些依赖组织成里程碑和门禁。需求细节以『docs/requirements.md』为准，产品方案背景以『docs/product-design.md』为准。

## 目标与非目标

### 项目目标

- 交付可被开发、测试和发布人员共同引用的 v0.1.0 需求基线。
- 在业务代码开始前完成关键页面的交互文档和设计稿。
- 以统一随机核心、`ToolModule` 注册与会话协议实现塔罗、六爻、D20、硬币、扑克牌五个纵向切片。
- 用共享 UI 组件和 design tokens 建立全局样式单点修改能力，工具差异仅使用语义 token 和专属 primitive。
- 通过根目录 Makefile 为本地与 CI 提供一致、可验证且安全的构建入口。
- 通过独立测试角色验证规则、隐私、离线、恢复、跨端和无障碍。
- 以标准开源治理文件支持外部阅读、贡献、漏洞报告和许可审计。

### 项目非目标

- 项目经理不直接替代开发人员编写 Flutter、Dart、Web、Android 业务源码；代码由独立开发角色实现并由独立测试角色验证。
- 不在没有证据时升级 Flutter、依赖或平台工具链；可执行构建命令必须与实际验证结果一致。
- 不把设计稿、测试计划或发布报告伪造为已完成产物。
- 不在没有项目经理确认时扩大到账号、云同步、社区、完整排盘、商业化或新随机工具。

## 角色边界

### 项目经理子 agent

项目经理是当前主 agent，拥有跨角色协调和门禁裁决权。

- 冻结和维护『docs/requirements.md』、『docs/product-design.md』与本计划。
- 为每次范围变化分配稳定需求 ID，记录决策、待确认项、风险和影响。
- 指定交互设计、开发和测试子 agent 的输入、输出、边界和停止条件。
- 在里程碑间执行门禁检查，拒绝以“部分实现”替代未通过的 P0 验收。
- 汇总测试报告、许可证据和发布报告，做出继续、返工或阻塞决定。
- 当前阶段只编辑文档与治理文件，不编写业务源码。

项目经理不替代专业角色完成其主要交付物：设计稿由交互设计子 agent 负责，业务代码由开发子 agent 负责，测试代码和测试结论由测试子 agent 负责。

### 交互设计子 agent

- 读取已冻结需求和产品设计，建立关键页面信息架构、状态图、响应式布局和交互说明。
- 产出 docs/interaction-design.md 和归档到 docs 范围内的关键页面设计稿或设计稿索引。
- 使用平台 imagegen 的 gpt-image-2 生成任务产出高质量设计稿，不使用已否决的旧 built-in 图稿或其派生稿。
- 覆盖移动核心体验、五工具动效分镜、DND/D20 自定义骰池配置与结果、扑克配置与结果、塔罗/六爻解释页面、桌面响应式布局。
- 本轮增量覆盖 FR-053 的塔罗 `includeMinorArcana` 22/78 张牌组、默认值和许可降级，以及 FR-054 的五类玩法页简化结构、主操作/重置、高级选项折叠和结果/解析下置。
- 为塔罗、六爻、D20、硬币和扑克牌分别提供按压、生成、揭示、完成、减少动态效果五态静态分镜，并说明振动开启/关闭和 Web 能力降级。
- 明确正常、空、错误、离线、存储不可用、减少动态效果、大字体、键盘和屏幕阅读器状态。
- 为塔罗、六爻、D20、硬币、扑克牌分别说明随机结果如何先冻结、再动画展示；硬币包含抛起/翻转/落定，扑克牌包含洗牌/抽牌。
- 为生成式图像资产记录用途、提示词、生成时间、可获得的工具/模型信息、原始尺寸、4K 评审副本、编辑关系和许可待核查状态；平台未返回的模型元数据不得推定。
- 使用交互文档和设计 tokens 定义精确行为与数值；图像稿只承载视觉和分镜，不覆盖 tokens。
- 不得把未审核资产标记为可发布，也不得把当前尚未生成的设计稿写成已完成。
- 不修改需求 ID 的语义，不编写业务源码，不替开发做依赖选型。

### 开发人员子 agent

- 只有在 G1 设计就绪门禁通过后，才开始业务源码和工程配置。
- 按需求 ID 实现统一随机核心、规则模块、会话、存储、页面、分享和平台适配。
- 实现统一 `ToolModule` 注册、会话 envelope、随机调用、历史/分享集成；新增工具不得要求修改应用 shell 或复制共享管线。
- 建立共享 UI 组件、design tokens、语义 token 与专属 primitive，确保全局按钮等公共样式可单点修改。
- 在根目录实现 Makefile 命令契约，保持本地与 CI 一致，不把未验证命令写成可用。
- 保持规则层、内容层、会话层和 UI 层边界，提供固定随机向量和可复查结果。
- 对不清晰的需求先向项目经理提交影响分析，不在代码中静默猜测。
- 提供实现映射、Makefile 实际可执行证据、fake 模块架构测试、变更摘要和已知限制。
- 不擅自删除或重写设计稿、需求和许可记录。

### 测试人员子 agent

- 在开发交付后读取需求、设计和实现映射，补充必要的单元、组件、端到端、统计、无障碍和兼容性测试。
- 验证扑克无放回与跨端顺序、五工具反馈/触觉降级、解释内容边界、Makefile 目标，以及 fake 模块不修改 shell 的架构契约。
- 产出 docs/test-plan.md，并在验证后形成带证据的测试结果。
- 对规则错误、数据丢失、隐私泄露、随机源降级、跨端不一致和关键页面阻塞进行优先升级。
- 明确通过、失败、阻塞、未覆盖和待确认，不用绿色汇总掩盖子项失败。
- 复测修复项并维护需求 ID 到测试证据的追踪。
- 不改变产品范围或用例预期；发现需求矛盾时交由项目经理裁决。

- 任一玩法页仍将所有配置平铺在主操作区、存在多个随机主按钮、重置会触发随机，或结果/解析遮挡核心操作。

- 未说明 Android 分阶段触觉、关闭振动、Web 能力检测/静默降级和“静态导航不强制震动”的反馈边界。
- 生成式或第三方资产没有记录来源和许可状态。
- 设计稿与需求的核心规则、隐私默认值或内容边界冲突。

### G1 设计就绪门禁

**状态**：【PASS】。旧 built-in 设计稿全部【已否决】并只作审计证据；Expanded Round-4 八项资产和十一张活动设计证据已通过独立验收。原始图尺寸、SHA-256、4K/1600×1000 确定性副本、拼版坐标和 RMSE 均已记录；平台未提供的底层模型版本不被虚构。G1 PASS 不改变设计稿的 `runtimeAsset=false` 边界；v0.1.1 的独立运行时实体资源另见资产合同，许可仍待复核。

对应模块开发开始前必须由项目经理确认以下项目全部满足；当前 G1 证据已逐项满足：

- 所有活动视觉稿均来自指定 gpt-image-2 生成任务，附原始输出、提示词、SHA-256 和确定性 4K 评审副本；模型元数据与原生尺寸只按平台实际返回信息记录。
- 视觉稿体现现代界面层级、一致组件、克制材质/光影和高质量微动效，不能以静态平铺或装饰效果替代状态连续性。
