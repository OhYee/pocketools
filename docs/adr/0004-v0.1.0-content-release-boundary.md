# ADR：v0.1.0 内容发布边界

- **状态**：Accepted；运行时内容元数据与许可清单同步后生效。
- **日期**：2026-08-23。
- **适用版本**：v0.1.0。
- **决策所有者**：项目经理。

## 背景

Pocketools 的塔罗与六爻需要提供必要解释，但解释能力不能把来源不明的现代文章、牌面插画、古典排版版本或第三方规则文本带入开源发布。交互设计生成图只用于实现参考，运行时界面使用代码绘制 primitive 和 Material 图标。

Stage 2B2 与 Stage 2B3 的独立 QA 已检查内容覆盖、元数据、免责声明和范围禁语。发布仍需要把候选状态转换为明确、可复查的内容许可结论。

## 决策

### 塔罗内容

v0.1.0 发布 \`TarotContentCatalog\` 中由 Pocketools 贡献者为本项目创作的中文关键词、象征概述、正逆位反思提示和问题。该内容按项目 Apache-2.0 许可证发布。

标准的 78 张牌名称、大小阿尔克那结构、花色与序数用于稳定标识和通用牌组结构；它们不构成对某一现代作者解释、特定牌面插画或数字修复牌组的引入。

首版不包含第三方牌面、书籍或网站的现代释义、逐字摘录、外部字体、音效或运行时生成图。代码只绘制抽象牌面 primitive。

### 六爻内容

v0.1.0 发布 \`LiuyaoContentCatalog\` 中由 Pocketools 贡献者创作的上下卦结构说明、变化关系和开放式反思提示，并按 Apache-2.0 许可证发布。

八卦名称、阴阳线、六十四卦名称、King Wen 编号和上下卦映射只作为规则数据、稳定标识及传统术语使用。首版不嵌入古典卦辞或爻辞、现代译文、第三方注释和排版数据库。

首版明确不实现纳甲、六亲、世应、旬空、神煞、用神或自动吉凶断语；结构说明不构成确定性预测或专业建议。

### 其他工具

- D20 使用通用骰池、修正值、目标值和优势/劣势描述，不引入 D&D 商标素材、角色、世界观、插画或第三方 SRD 规则正文。
- 扑克牌使用标准花色、点数和大小王名称，以代码绘制抽象牌面；不包含赌场、下注、筹码、赔率或博彩导流内容。
- 硬币使用用户可编辑的两面标签与二值随机规则，不引入货币图案或第三方商标。

### 生成式设计稿

\`docs/design\` 与 \`output/imagegen\` 中的生成式页面稿继续标记为 \`runtimeAsset=false\`，只用于交互和视觉评审。它们不注册进 \`pubspec.yaml\`，不进入应用资源、分享卡或首版商店素材。

平台图像生成任务没有暴露可由仓库机器验证的底层模型元数据，因此文档只能记录任务使用了平台请求的 gpt-image-2 能力、提示词、原始输出和确定性评审副本，不能虚构更细的模型证明。4K 评审副本是确定性缩放/排版产物，不宣称为模型原生 4K 输出。

## 发布要求

发布候选必须同时满足：

- 塔罗与六爻运行时 source metadata 标记 \`Apache-2.0\` 和 \`approved for v0.1.0 project release\`，不再出现 candidate。
- 内容校验测试覆盖完整 78 张塔罗与 64 卦，并证明外部现代释义、传统原文和运行时 artwork 未被声明引入。
- 设置中的内容与第三方许可入口可达，并显示作者、版本、来源、许可、免责声明和能力边界。
- \`docs/licensing.md\`、NOTICE、运行时元数据和实际 asset manifest 一致。
- 任何后续外部文本、牌面、字体、音效或生成资产在进入运行时前单独记录来源、版本、再分发许可和归属。

## 后果

首版可以提供完整但克制的文化解释，同时避免把来源不明内容包装成开源资产。代价是视觉牌面保持抽象、六爻解释不扩展到完整排盘；后续内容增强必须经过独立许可审查和内容测试，不能直接粘贴到 catalog。
