## 多重占卜交互增量

多重占卜的规则、状态、解释优先级和会话字段以[多重占卜设计与实现说明](multi-divination-design.md)为准。本节只记录与共享交互合同的关系：

- 初始态只有一个有厚度的塔罗牌堆和操作提示；点击牌堆一次追加一组三张 A/B/C，六次完成六爻，不提供独立的“查看过程”区域。
- 牌面按抽取顺序逐组进入页面；新增组可以动画，既有组不重播、不重新布局。牌堆、单组牌面和 A 牌释义都使用塔罗的共享底层组件。
- 点击 A 牌打开既有塔罗释义弹层；B/C 在标准模式中只作为透明随机输入，不生成额外解释。
- 完成后主卦、动爻、变卦和 A1～A6 摘要合并到顶部实体区域；详细解释位于同页下方的内容区，不形成第二个动画舞台。
- 高级选项默认折叠，当前会话开始后仍可编辑，修改内容在下一轮生效；返回、刷新和后台恢复使用同一会话与已保存的一次性牌序。
- 页面主体复用共享 `AppEntityStateView`，Web 桌面保持左侧栏、右侧主体并从主体顶部对齐；不添加隐藏全高占位或页面级 hack。

## 参考图效果增量

用户提供的日／夜主题设计板作为构图和材料感参考，精确交互仍以本文和 `tokens.json` 为准。已落地的共性约束如下：

- 页面保持中性画布；工具色只进入主按钮、选中边框、实体图形、结果 accent 和弱表面，不把整页染成工具色。
- 六个玩法页共享“顶部实体舞台（状态／动画／结果） → 唯一主操作与条件性重置 → 折叠高级选项 → 可选解析”的结构；不再渲染与实体舞台并列的结果或“查看过程”展示层。实体舞台使用统一 halo、边框和层级，避免每个页面各自定义卡片。
- D20 主实体使用移动端 `176 px`、桌面端 `208 px`；总值、公式、DC 和必要骰明细作为实体舞台内的结果摘要，不再单独占用结果层。小骰子只用于实体舞台内的紧凑明细。
- 硬币就绪态展示本地实体正面，抛掷中使用正面／反面／边缘素材和透视翻转；六爻就绪态展示三枚实体硬币，当前爻揭示复用同一物理硬币 primitive。
- D20 的滚动阶段和停止阶段均使用实体 D20 资产；扑克牌堆使用带双层边框、交叉纹理和中心菱形的牌背，牌面使用白底、角标、花色和阴影表达真实纸牌层级。
- 塔罗完成态核心区展示真实牌面，生成／揭示／完成动画均留在实体舞台；扑克按冻结顺序在实体舞台内进入响应式网格，牌面比例为 `2:3`，抽牌允许不超过 `4°` 的轻微旋转。

## 本轮实现增量合同

本节是当前源码和测试的权威交互合同；历史设计稿中仍出现“查看过程”或完成后禁用按钮的画面，仅作为设计演进记录，不作为当前实现验收标准。

### 顶部实体状态

- `AppEntityStateView` 是每个玩法唯一的实体舞台，内部组合实体 primitive、`AppGenerationStateView` 状态胶囊、动画和结果摘要；`AppGenerationStateView` 不是第二个舞台或独立结果层。
- D20/DND、硬币和六爻的实体命中区统一由 `AppPhysicalAction` 提供：最小 `48 × 48 px`、键盘焦点、语义标签和 Web hover/splash 反馈由共享组件负责；新增玩法只需要提供实体 child 和 `primaryAction`。
- 塔罗和扑克统一使用 `AppPhysicalDeck` + `AppDeckResultFlow`；牌堆命中每次只追加一张牌，`n` 只表示本轮目标数量。
- 结果在随机层生成并保存后才进入揭示；`generating`、`revealing`、`completed` 都在顶部实体舞台可见，不能只在页面下方显示动画。
- 完成结果和解析直接合并到顶部实体区域；下方只保留空态提示、跳过／逐张操作、会话分享和必要的解释补充，不重复渲染结果卡。
- 页面不再提供名为“查看过程”的独立展开层。规则版本、算法版本和原始序列继续保存在会话与分享载荷中。
- 六爻不再在完成结果下方渲染“形成过程”卡；六爻图、动爻、变卦和原创结构简释构成用户可见的结果与解释，原始三枚硬币序列仍由会话、历史和分享载荷追溯。
- 六爻自动模式的三枚铜钱固定位于卦象上方；只有三枚铜钱的实体命中区触发下一爻，卦象命中区只打开当前爻信息或完整卦象含义，不触发投币。内容来源与许可元数据保留在内容包和审计文档中，不在六爻玩法页面展示。

### 实体即操作入口

实体点击、键盘激活和主按钮共用同一个 `primaryAction`，不维护两套随机路径。

| 场景 | 点击实体 | 完成态主按钮 | 独立重置 | 说明 |
| :--- | :--- | :--- | :---: | :--- |
| 塔罗 | 牌堆每次抽一张；牌面打开释义 | `再抽一张`，创建关联新会话 | 保留 | 多牌阵按位置逐次追加，部分结果可恢复 |
| 扑克牌 | 牌堆每次只抽一张；`n` 保留为本轮目标数量 | 达到目标后继续抽一张并创建关联会话 | 保留 | 无放回、顺序冻结；重复操作只追加新牌，不改写旧结果 |
| D20 | 点击骰体执行掷骰 | `重置并再掷` | 不显示 | 先清理当前展示，再按同一配置生成并保存新结果 |
| 硬币 | 点击硬币执行抛掷 | `再抛一次`，语义等价于重置并重新抛掷 | 不显示 | 单次／批量／自定义标签均沿用同一配置 |
| 六爻 | 点击三枚硬币／当前爻继续起卦 | 完成后 `再起一卦` | 完成前保留 | 六次逐爻流程不改变原爻序，完成后创建新草稿 |

- 操作进行中才暂时禁用同一会话的重复提交；完成后主按钮恢复可用。
- 抽牌类的重置清除当前视觉结果但不删除历史、不请求随机值；下一次抽取创建新会话。
- 硬币和 D20 不提供额外重置按钮，主操作在完成态负责 reset + generate，保存新结果失败时保留旧结果。

### 体感抛硬币

- Android 通过 `pocketools/motion_sensor` 与 `pocketools/motion_sensor/events` 接入系统加速度计，不需要运行时权限；加速度采样只触发既有抛硬币主操作，不直接生成随机值。
- `ShakeMotionTrigger` 使用三轴合成模长阈值 `18.0 m/s²` 和 `900 ms` 冷却窗口，过滤普通姿态变化并避免一次摇动重复抛掷。
- Web、非 Android、传感器启动失败、用户关闭反馈或减少动态时，页面保留硬币点击和主按钮；体感入口显示能力降级提示，不阻塞手动操作。
- 体感触发与手动触发共享冻结、保存、动画和反馈链路；不允许体感成为绕过会话、随机源或安全校验的第二入口。
- 自动化已覆盖阈值、三轴模长、冷却窗口、Android channel 启动和手动 fallback；真实 Android 设备的传感器采样、安装和振动仍标记为【待验证】。

### 减少动态与反馈

- 正常模式保留实体级抛起／翻转／落定、骰体滚动、牌背洗牌和塔罗翻牌；结果始终来自同一冻结 outcome。
- 减少动态模式只缩短到 `80 ms` 的透明度／状态过渡，不重抽、不跳过解释、不隐藏结果。
- 反馈服务只在提交、首次揭示和完成阶段发出语义反馈；不逐枚硬币、逐颗骰子或逐张牌震动。Web 和不支持平台为 no-op。

## TL;DR

- **结构**：移动端使用“首页、历史、设置”底部导航；桌面端使用同顺序左侧栏；首页内包含塔罗、六爻、D20、硬币、扑克牌和多重占卜六个工具入口，页面路由与语义不随视口改变。
- **核心流程**：选择工具、配置、明确开始、生成并持久化结果、在顶部实体区揭示并完成；常用单次操作从首页开始不超过 3 次主要交互。
- **简化玩法页**：默认先展示承载状态／动画／结果的顶部实体、一个主操作和条件性“重置”；高级选项默认折叠，可用解析不再与“查看过程”层绑定；塔罗默认一次点击抽一张牌。
- **完成后操作**：抽牌类再次激活主按钮创建新的抽取会话；硬币／D20 再次激活主按钮先清理当前显示结果再开始同配置的新投掷，完成态不显示独立重置按钮。
- **状态底线**：动画开始前结果必须已经生成并写入可恢复会话；重复点击、返回、刷新和恢复不产生第二个结果。
- **适配底线**：覆盖 360 × 800、小屏手机、平板和 1440 × 900；支持触摸、鼠标、键盘、屏幕阅读器、200% 字体和减少动态效果。
- **隐私底线**：问题、备注、标签和结果只在本地处理；分享必须预览且默认排除私人字段；v0.1.0 不采集匿名分析。
- **共享实现底线**：六个工具统一复用 `AppToolScaffold`、`AppButton`、`AppStepper`、`AppSegmentedControl`、`AppEntityStateView` 与 `AppNavShell`；`AppEntityStateView` 内部仅以 `AppGenerationStateView` 作为状态胶囊，`AppResultCard` 若保留只能作为舞台内的结果摘要，不得成为独立结果层；工具差异只通过语义主题和少量 visual primitive 注入。
- **门禁结论**：Round-3 的 `02`、`03`、`05` 按限定范围通过，`04` 延续 accepted；Expanded Round-4 八个资产及 revision-2 assembled 全部通过，十一张活动文件形成实现基线。旧 `01` 四工具首页继续 superseded/audit-only，Round-3 Web `06a/06b` 继续 scope-invalidated/audit-only。G1 的交互与视觉设计范围为【PASS】，但图片仍为 `runtimeAsset=false`、内部设计参考、待 PM 最终许可复核。

## 设计原则

- **现代工具箱**：应用壳保持中性、清晰、效率优先；六个工具只在语义强调色、主题表面与专属 visual primitive 上建立差异。
- **先结果，后仪式**：随机生成、规则计算和持久化是一次原子操作；揭牌、投币、掷骰、翻硬币只展示同一份结果。
- **结论与可追溯元数据分层**：主结果先出现在顶部实体舞台；原始随机值、转换规则、规则版本和算法版本继续写入不可变会话、历史和分享载荷，但玩法页不渲染名为“查看过程”的独立展示层。
- **完成后仍可继续操作**：完成态主按钮不因结果存在而禁用；抽牌类开始新的抽取，硬币／D20 类以同一配置执行重置加新投掷。旧会话在新结果持久化前不得被覆盖或丢失。
- **操作可撤销，结果不可改写**：草稿可返回和撤销；完成结果只读；“再来一次”和“调整配置”均创建新草稿。
- **离线是正常能力**：离线不阻止六个工具、历史、预设复用和文本复制；界面只提示在线能力不可用，不把离线描述为随机失败。
- **文字承担语义**：正逆位、阴阳与动静、达到与未达到都必须有文字或形状，不依赖颜色、朝向或动画。

### 页面树

```text
应用壳
├── 首页 /
│   ├── 继续使用
│   ├── 工具入口
│   │   ├── 塔罗 /tools/tarot
│   │   ├── 六爻起卦 /tools/liuyao
│   │   ├── D20 检定 /tools/d20
│   │   ├── 抛硬币 /tools/coin
│   │   └── 抽扑克牌 /tools/cards
│   └── 最近结果
├── 会话 /sessions/{id}
│   ├── 执行与揭示
│   ├── 结果详情
│   └── 分享预览
├── 历史 /history
│   └── 历史详情 /sessions/{id}
└── 设置 /settings
    ├── 外观与反馈
    ├── 历史与隐私
    ├── 预设管理（次级界面）
    ├── 随机过程说明
    └── 内容许可与归属
```

- `/sessions/{id}` 只解析当前设备或浏览器中的本地会话。
- 分享预览是当前会话上的模态页或全屏页，不创建公开 URL，不修改会话。
- 工具配置保留在工具路由；产生结果后使用本地会话路由，刷新可以恢复同一结果。
- 未生成结果的简单草稿不进入历史；复杂配置只有用户明确保存为预设后才持久化。
- 预设管理从设置进入次级界面，继续使用三项一级导航；返回操作回到设置，不增加第四个入口。

### 一级导航

| 顺序 | 入口 | 图标语义 | 选中状态 | 保留状态 |
| :--: | :--- | :------- | :------- | :------- |
| 1 | 首页 | 房屋轮廓 | 图标与文字同时强调 | 保留首页滚动位置 |
| 2 | 历史 | 逆时针时钟 | 图标与文字同时强调 | 保留筛选、搜索和滚动位置 |
| 3 | 设置 | 齿轮 | 图标与文字同时强调 | 保留当前分组位置 |

### 移动底栏

- 适用宽度为小于 `1024 px`；固定在底部安全区之上，高度 `64 px + safe-area-bottom`。
- 三项等宽，图标 `24 px`，标签至少 `12 px`；触摸目标至少 `48 × 48 px`。
- 页面正文底部预留底栏、悬浮主操作和安全区的总高度，最后一个控件不得被遮挡。
- 在工具配置、执行和结果页仍显示底栏，但“生成”期间导航项进入语义禁用；用户触发返回使用『返回与恢复』规则。
- 200% 字体下标签允许两行但底栏不横向滚动；若系统文本导致高度增加，底栏随内容增高并保持三项等宽。

### 桌面侧栏

- 适用宽度为大于等于 `1024 px`；固定左侧，默认宽 `240 px`，内容区最大宽 `1200 px`。
- `1024～1199 px` 可收窄为 `88 px` 图标栏；每项通过可见提示和无障碍名称保留文字语义。
- `1200 px` 及以上显示 Pocketools 字标、三个一级入口和底部离线状态；不显示账号或云同步入口。
- 选中项使用背景、左侧指示条和字重三重反馈；键盘焦点环位于选中背景内侧。
- 侧栏与正文独立滚动；正文阅读顺序先标题、再内容，侧栏不会插入屏幕阅读器的页面主区域。

## 应用壳与通用布局

### 页面框架

- 顶部区域包含返回按钮、页面标题和最多两个次级操作；根页面不显示返回按钮。
- 主内容使用单一 `main` 地标；页面标题是该页面唯一可见主标题。
- 移动端页面水平边距 `16 px`；平板 `24 px`；桌面 `32 px`。
- 表单内容最大宽 `640 px`；结果与配置并列时每栏最小 `360 px`，栏间距 `24 px`。
- 移动端主操作使用底部粘性操作区；桌面端主操作跟随表单末尾，不使用覆盖内容的悬浮按钮。

### 通用页面标题区

- 左侧：返回按钮，仅次级页面显示。
- 中部：工具名或页面名；结果页副标题显示模式，不显示私人问题。
- 右侧：收藏、更多或帮助；破坏性操作不直接占用标题栏主位。
- 离线和临时会话提示位于标题下方，以状态横幅呈现，不用短暂 toast 承担关键状态。

### 共享 UI 组件合同

六个工具页面只能组合下列共享组件。组件从 `tokens.json` 读取基础样式；模块不得复制按钮、表单、导航、结果卡或会话状态视图。修改全局按钮高度、圆角、字体、边框或状态表现时，只改 `AppButton` 或对应 design token，六个工具与 fake 模块必须同步生效。

| `AppToolScaffold` | `ToolModule` 描述、标题、顶部实体舞台、主操作、状态、配置区 | 工具标题、顶部实体／配置布局、粘性操作区、错误横幅与恢复入口 | 不生成随机值，不持有工具私有导航或私有会话格式；不渲染独立结果层 |

### 跨形态组件行为

- **移动**：小于 `1024 px` 使用底栏；工具表单单列，顶部实体舞台包含状态／动画／结果，主操作位于底栏上方且不遮挡最后一个字段。
- **桌面**：大于等于 `1024 px` 使用侧栏；配置和顶部实体舞台可双列，结果仍是实体舞台的一部分，不拆成“结果／过程”分栏；DOM、焦点和读屏顺序不改变。
- **200% 字体**：控件增高并换行；分段控件转纵向单选卡，步进器转三行，不截断按钮标签，不用横向滚动完成任务。
- **键盘**：所有共享控件遵循 roving focus 或平台等价单选语义；`Tab` 离开复合控件，方向键只在控件内部移动，提交锁覆盖重复 `Enter`。
- **屏幕阅读器**：页面、状态、字段、当前值、范围、结果、实体动作与错误分别有名称；visual primitive 只提供结构化文字等价内容，装饰层从语义树隐藏。实体动作与主按钮共享同一可访问名称和提交锁。

### 首次使用

- 首次启动不使用多页强制引导，直接进入首页，并在六个工具卡上提供简短用途说明。
- 首次进入塔罗或六爻时显示一次底部说明页，标题为“开始前请了解”，正文为“结果用于娱乐、文化学习和自我反思，不是专业建议。”

## 统一会话模型

### 状态定义

| 状态 | 可编辑输入 | 可请求随机值 | 可导航离开 | 持久化要求 | 主界面反馈 |
| :--- | :--------: | :----------: | :--------: | :--------- | :----------- |
| 草稿 `draft` | 是 | 否 | 是 | 不要求 | 表单和校验提示 |
| 就绪 `ready` | 是 | 仅明确开始后 | 是 | 不要求 | 主按钮可用 |
| 生成 `generating` | 否 | 仅一次 | 受保护 | 建立待完成记录 | 按钮禁用，显示“正在生成结果…” |
| 已生成 `generated` | 否 | 否 | 受保护 | 结果必须可恢复 | 不对用户单独停留 |
| 揭示 `revealing` | 否 | 否 | 是 | 已持久化 | 播放或跳过展示动画 |
| 已完成 `completed` | 否 | 否 | 是 | 按历史设置保存 | 只读结果与操作 |
| 临时 `ephemeral` | 视阶段而定 | 按正常规则 | 是 | 仅当前生命周期 | 常驻“本次结果不会保存”横幅 |
| 阻塞 `blocked` | 是 | 否 | 是 | 保留草稿 | 可恢复错误与处理入口 |

### 生成与揭示顺序

1. 用户激活主按钮，界面再次同步校验全部输入。
2. 校验通过后冻结结构化输入、规则版本、算法版本和内容包版本。
3. 创建会话 ID，主按钮立即禁用并设置 `aria-busy=true`。
4. 规则层一次性生成完整原始随机结果和转换结果。
5. 持久化可恢复的完整结果；历史关闭时写入仅当前生命周期的会话仓库。
6. 持久化成功后进入揭示；存储不可用时先让用户确认临时会话，再按临时模式生成。
7. 动画只读取已生成结果；跳过动画直接展示同一结果。
8. 动画结束、页面隐藏或减少动态效果启用时进入已完成状态。

- 生成期间的重复点击、`Enter` 重复触发、双击和触摸连点全部复用同一个提交锁。
- 顶部实体的点击、键盘激活和主按钮必须调用同一个类型化 `primaryAction`；禁止为实体和按钮各自维护随机或会话路径。一次用户激活最多创建一个会话。
- 若安全随机源不可用，在第 4 步停止；不创建伪结果，不使用时间戳或普通随机回退。
- 若结果已生成但动画中断，恢复时直接打开该结果；可以重新播放纯展示动画，但默认不自动播放。
- 若写入持久化存储失败且结果尚未生成，回到可编辑配置并提供“使用临时会话”；若结果已经完整生成到生命周期仓库，则显示结果和临时状态，不重新生成。
- 完成态点击硬币或 D20 的“再抛一次”必须先成功创建并保存新结果，再替换顶部实体显示；保存失败时保留旧会话和旧结果，不把失败的重置误报为成功。

### 返回与恢复

| 所在状态 | 系统返回、浏览器后退或页面关闭行为 |
| :------- | :--------------------------------- |
| 草稿且未修改 | 直接返回来源页 |
| 草稿且已修改 | 返回时保留当前内存草稿；离开应用前提示“放弃未保存的配置？” |
| 生成 | 拦截离开并显示“结果正在生成，完成后可在这里恢复”；等待完成或选择留在当前页，不取消已开始的生成 |
| 揭示 | 允许离开；结果已经保存，返回时直接进入已完成结果 |
| 已完成 | 直接返回来源页；刷新或恢复仍定位到同一会话 |
| 临时已完成 | 离开前提示“退出后可能无法找回此结果”，提供“复制结果”和“继续退出” |

- 模态框和底部说明页优先消费返回操作；关闭后焦点回到触发控件。
- 从历史详情进入结果页时，返回历史并恢复筛选与滚动位置。
- 从分享预览返回时，不改变字段选择以外的任何会话数据；取消系统分享仍停留在预览或结果页。
- 简化玩法页的“重置”只清理当前未提交草稿；若页面已有完成结果，则打开新的空白草稿并保留旧会话。重置不取熵、不删除历史、不触发新的揭示动画。
- 恢复时保留核心实体状态、主操作与重置位置、高级选项展开状态和同一会话的结果；恢复不能用默认值覆盖 `includeMinorArcana` 或其他已冻结配置。

#### 顶部实体动作合同

- 六个工具的顶部实体都是当前主操作入口：点击塔罗／扑克牌／多重占卜牌堆直接抽牌，点击硬币直接抛硬币；D20、六爻和其他实体同样把点击映射到当前主操作，不另建随机路径。
- 主按钮继续保留，用于键盘、屏幕阅读器、触摸目标不便点击实体或用户需要明确动作时；实体和按钮共享同一个 `primaryAction`、参数快照、提交锁、错误处理、焦点回收和会话创建结果。
- `ready` 且配置有效时，实体和主按钮均可激活；`generating`／`revealing` 时两者均忙碌或语义禁用；`completed` 时按『完成态主操作与重置可见性』执行新的抽取或重投掷。
- 实体点击区域至少 `48 × 48 px`，视觉图形可大于点击区域；实体装饰层从语义树隐藏，实体语义节点必须读出动作和当前状态，例如“硬币，准备就绪，点击抛一次”。
- 双击、连续点击、键盘 `Enter`／`Space` 和实体点击与主按钮的竞态都只能命中一次提交；动画重播、跳过或恢复不重新调用 `primaryAction`。

- 顶部实体区是唯一的执行舞台：同一实体区同时承载 `ready`、`generating`、`revealing`、`completed` 的状态胶囊、实体动画和主结果摘要；不再在实体区外渲染独立的“生成状态”“结果”或“查看过程”层。
- 原始随机值、转换规则、规则版本、算法版本和内容版本仍写入不可变会话、历史与分享载荷；它们不是玩法页上的“查看过程”入口。可面向用户的解释只在实体区下方显示。

#### 硬币体感抛掷（历史设计草案）

本小节记录早期的 Web／Android 权限与灵敏度候选方案，已被『本轮实现增量合同』中的 Android 加速度计桥、`18.0 m/s²` 阈值、`900 ms` 冷却和 Web／非 Android 手动降级取代。

- **启用入口**：【设计已冻结，待实现】抛硬币页“高级选项”内提供“体感抛掷”开关，默认关闭；开关旁说明“摇动设备触发一次当前抛掷，仍使用本地安全随机”。开启后首次使用先展示一次说明，不在页面加载时主动请求传感器权限。设置页可提供同一入口的快捷跳转，但不产生第二个配置源。
- **Android 权限与能力**：用户明确打开开关后才检测并申请实现所需的设备运动权限；不需要运行时权限的设备不弹权限框。加速度／线性加速度传感器缺失、权限拒绝、系统策略禁用、初始化超时或监听失败时，将入口置为不可用并显示“此设备不支持体感抛掷”，保留点击硬币和主按钮；不阻塞手动抛掷，不创建伪结果。
- **Web 权限与能力**：只在安全上下文、用户明确开启且存在 `DeviceMotionEvent`／等价能力时请求平台允许的权限；需要 `requestPermission` 时必须由开关点击触发。拒绝、超时、跨域策略禁止、页面不可见或能力检测失败均降级为手动点击，并显示“体感抛掷不可用，仍可点击硬币或主按钮”。
- **灵敏度**：提供“灵敏、标准、稳健”三档，默认“标准”。以设备无关的线性加速度峰值作为判定量，连续至少 `60 ms` 超过阈值才算一次有效手势；阈值分别为 `1.4 g`、`1.8 g`、`2.2 g`。不使用方向、摇动次数或最后一帧角度推导硬币面值。
- **冷却与状态**：有效手势接受后进入 `pressed`／`generating`，冷却 `1000 ms`；冷却期间和 `generating`／`revealing`／`completed` 期间的传感器事件全部丢弃，不排队、不补抛。批量模式一次手势只触发一次完整批次，率先达到模式也只创建一个结果。新的手势必须等回到 `ready` 且冷却结束；冷却状态显示“体感抛掷冷却中”，不把冷却误报为随机失败。
- **减少动态**：`reduce motion` 不关闭体感输入，也不改变阈值、冷却、随机和会话；接受手势后跳过抛起／翻转／落定 transform，在顶部实体内以 `80 ms` 以内的透明度收束或直接显示冻结结果。振动仍遵循独立的反馈开关和平台降级规则。
- **桌面 Web**：默认不启用、不自动请求权限；若桌面浏览器没有传感器能力，开关显示不可用原因，键盘、主按钮和硬币点击始终可用。若用户明确开启且浏览器报告能力，仍必须遵守用户激活、页面可见、安全上下文、权限和 `1000 ms` 冷却约束；传感器不能成为桌面 Web 的必需路径。

- **历史源码状态**：【已关闭】本行只描述实现前审计时未接入传感器的状态；当前实现证据见 `lib/core/platform/motion_sensor.dart`、`android/app/src/main/kotlin/dev/pocketools/pocketools/MainActivity.kt` 和 `test/features/coin/motion_sensor_test.dart`。

### D20 配置

#### 模式与预设

- 初始页顶部按 `diceCount` 展示对应数量的实体骰子；每枚骰子均可点击掷骰。顶部展示 `aDb` 快速配置（例如 `1D20`），由骰子数和骰面两个数字加减框组成，不使用文本输入；模式、骰池、modifier 和 DC 位于默认收起的“高级选项”内。
- 高级选项内的模式控件按“普通、优势、劣势、自定义”排序；小屏或 200% 字体下改为两列或纵向单选卡，不横向滚动。
- 普通映射为 `diceCount=1`、`diceSides=20`、`aggregation=sum`；优势映射为 `2`、`20`、`keepHighest K=1`；劣势映射为 `2`、`20`、`keepLowest K=1`。
- 选择预设会一次性写入统一骰池字段；预设不是独立计算分支，结果、历史和分享都消费同一结构化配置。
- 选择“自定义”时保留当前骰池值；从预设第一次编辑数量、面数、聚合或 K 时，模式立即显示“自定义”，不重置 `modifier`、DC 或检定名称。
- 自定义值恢复为某个预设的完整字段组合时，模式标签恢复为对应预设；若多个组合不可能同时匹配，则按普通、优势、劣势的固定顺序匹配。
- 模式变化只更新草稿和只读摘要，不生成骰点；开始后模式标签与字段一起冻结。

#### 自定义骰池字段

| 字段 | 控件与范围 | 显示规则 | 错误文案 |
| :--- | :--------- | :------- | :------- |
| 骰子数量 `diceCount` | 减号、整数输入、加号；`1～20`，默认 `1` | 摘要显示“掷 N 枚” | “请输入 1～20 的整数。” |
| 骰子面数 `diceSides` | `D4、D6、D8、D10、D12、D20、D100` 快捷项，加“自定义面数”整数输入；`2～1000`，默认 `20` | 快捷项和输入写入同一字段；非快捷值选中“自定义” | “请输入 2～1000 的整数。” |
| 聚合 `aggregation` | 单选“全部求和、保留最高、保留最低” | 分别映射 `sum`、`keepHighest`、`keepLowest` | “请选择一种聚合方式。” |
| 保留数量 `K` | 减号、整数输入、加号；`1～diceCount` | 仅保留最高／最低时出现；`sum` 下不提交 K | “请输入 1～当前骰子数量的整数。” |
| 修正值 `modifier` | 减号、带符号整数输入、加号；默认 `0` | 正数显示 `+N`，负数显示 `−N`，零显示 `0` | “请输入有效的整数修正值。” |
| 难度 `DC` | “与 DC 比较”开关加整数输入；可选 | 关闭时结构化字段为 `null`，不显示达到／未达到 | “请输入有效的整数 DC。” |

- `modifier` 和 DC 的最终数值边界由冻结规则校验器统一定义；界面不得用截断、四舍五入或静默回退修正非法输入。
- 关闭 DC 时保留本次草稿中的最近输入值供重新开启，但提交结构化配置时写入 `null`；离开草稿后不把该未启用值写入结果。
- K 大于新 `diceCount` 时不静默改小：字段保持原输入、显示内联错误并禁用“掷骰”；用户可自行调整 K 或数量。
- 从保留模式切换到 `sum` 时保留草稿内最近 K 供返回使用，但摘要、提交和结果均不包含 K。
- 主按钮为“掷骰”；只读摘要必须完整，例如“自定义 · 4D20 · 保留最高 3 · +5 · DC 35”。
- 不提供自然 1 自动失败或自然 20 自动成功开关；规则说明固定写“自然 1 或 20 不自动决定成败”。

#### 步进器、键盘与错误恢复

- 减号和加号各为独立 `48 × 48 px` 按钮；点击或按键每次只改变 `1`，到边界时对应按钮禁用并保留原因语义。
- 长按可在 `500 ms` 后以每 `120 ms` 一次重复步进，松开、移出、失焦、页面隐藏或达到边界立即停止；重复步进只改草稿，不触发生成。
- 数字输入允许用户暂时清空或输入中间态；失焦和开始时执行整数与范围校验。错误期间保留原字符串，不自动替换成默认值。
- 输入聚焦时，`ArrowUp`／`ArrowDown` 分别增减 `1`，`PageUp`／`PageDown` 分别增减 `10` 并夹在合法边界内；`Home`／`End` 设置为下界／上界。K 的上界随当前 `diceCount` 更新。
- `Enter` 在单个输入中只提交字段并移动到下一逻辑字段；焦点位于主按钮时才开始检定。提交锁覆盖按键重复和双击。
- 开始失败时页面顶部错误摘要写“请修正 2 个骰池设置”，焦点移到第一个错误字段；摘要中的链接可依字段顺序跳转，字段错误与输入通过语义关联。
- 非法数量、面数、K、modifier 或 DC 均不创建会话、不消耗随机值，也不清空其他有效配置。

#### 快速 aDb 步进器

- 快速区只提供“骰子数 a”和“骰面 b”两个数字加减框，不提供文本输入或“应用表达式”按钮。
- 点击任一加减按钮立即更新同一组 `diceCount`、`diceSides` 字段，并立即刷新实体舞台中的骰子数量和视觉标签；不建立第二套骰池或计算路径。
- 快速区范围为 `diceCount=1～20`、`diceSides=2～1000`；完整聚合、K、modifier 和 DC 仍在高级选项中编辑。
- `NdS` 等安全表达式解析器如在领域层保留，只服务兼容性或数据迁移，不作为 v0.1.1 页面入口；页面的唯一快速配置路径是步进器。

#### D20 配置无障碍

- 模式组语义名称为“检定模式”；当前预设读作“优势，已选择，2 枚 20 面骰，保留最高 1 枚”。
- 步进器暴露单一数值字段语义及最小值、最大值、当前值；减号和加号名称包含对象，例如“减少骰子数量”“增加保留数量”，不能只读“减号”“加号”。
- 骰面快捷项读作“20 面骰，已选择”；选择“自定义面数”后焦点移动到面数输入，返回快捷项时不丢失键盘位置。
- 聚合与 K 的显隐变化通过礼貌实时区域播报，例如“已选择保留最高，请设置保留数量，范围 1 到 4”。
- 错误不只用红色表达；字段边框、错误图标、错误文字和读屏错误状态同时出现。

### 硬币配置

- 初始页顶部展示一枚中性硬币；主按钮为“抛一次”，相邻为“重置”。批量、自定义标签和“率先达到”均位于默认收起的“高级选项”内。
- 模式为“单次、批量”；单次默认不展示次数，主按钮“抛一次”。
- 批量快捷次数为 `3、5、10`，另有 `1～100` 步进与数字输入；默认 `3`。
- “自定义两面”展开后显示“正面标签”“反面标签”；去除首尾空格后相同则报错“两个标签不能相同”。空值回退“正面／反面”。
- “率先达到”位于批量高级选项；启用后输入目标 `N`，摘要明确“任一面先达到 N 次即停止”。
- 批量主按钮为“抛 3 次”或“开始，率先达到 2 次”；超出范围时按钮禁用且不生成结果。

### 扑克牌配置

- 初始页顶部展示牌堆牌背；主按钮为“洗牌并抽取”，相邻为“重置”。大小王、抽取数量和牌组摘要位于默认收起的“高级选项”内。
- 页面标题为“抽扑克牌”；牌组摘要和控件使用稳定字段 `includeJokers`、`deckSize`、`drawCount`，显示名称不作为数据主键。
- “包含大小王”使用 `SwitchRow`，PM 决策默认关闭，即 `includeJokers=false`、`deckSize=52`；用户显式开启后才变为 `deckSize=54`，并显示“两张大小王使用不同稳定 ID”。
- 抽取数量使用 `AppStepper` 与整数输入，字段名“抽取数量”，范围动态为 `1～deckSize`；默认示例为 `3`。切换牌组后若当前字符串越界，保留原输入并显示“请输入 1～当前牌组大小的整数。”，不得静默截断。
- 冻结前摘要逐字展示“标准牌组 · 不含大小王 · 52 张 · 抽取 3 张 · 无放回”；开启大小王时同步改为“54 张”，不得出现 53 或不明确的“完整牌组”。
- 主按钮与牌堆共用同一抽牌动作；开始后同时冻结 `includeJokers`、`deckSize`、`drawCount`、规则版本和算法版本，`drawCount` 只作为本轮目标，本次只把一张牌写入可恢复会话，部分目标会话允许继续追加。
- `drawCount < 1`、`drawCount > deckSize`、非整数、牌组损坏或安全随机源不可用时，不创建会话、不消耗随机值；错误聚焦数量字段或对应状态横幅。
- 牌面只允许原创或许可明确的抽象标准花色、点数与大小王标记；禁止赌场桌面、筹码、下注、赔率、现金、荷官、输赢或第三方牌背。

## 执行与揭示

### 通用执行舞台

- 顶部实体舞台同时保留工具实体、状态胶囊和“结果已安全生成”状态；不要在动画前展示具体结果，但生成后的冻结结果必须继续留在同一舞台中。
- 舞台最小高度 `240 px`；200% 字体或小屏时允许缩小图形，不能缩小文字。状态、生成／揭示动画、完成结果、必要摘要和“跳过动画”都在同一舞台内。
- 逐步流程在舞台内提供进度文本，例如“第 2／6 爻”；解析和解释位于舞台下方。
- 执行期间所有会触发随机值的控件禁用；可访问名称附加“正在生成”或“结果已生成，正在揭示”。
- 揭示完成后主焦点移动到顶部实体结果标题；屏幕阅读器使用礼貌播报，不逐帧播报动画。

### 五态动效合同

- 所有工具使用“按压、生成、揭示、完成、减少动态效果”五态；精确时长、缓动、位移、缩放、模糊和粒子上限以 [设计系统](design/design-system.md) 与 [设计令牌](design/tokens.json) 为准；硬币实体抛掷、D20 实体滚动停面、塔罗真实抽牌翻牌和运行时资产清单以 [Runtime visual asset & motion contract](design/runtime-visual-asset-motion-contract.md) 为准。
- 按压只确认输入；生成只表现任务已锁定；揭示只读取持久化结果；完成只强化主结果；任一视觉状态都不能访问随机源或推进规则计算。
- 用户点击“跳过动画”、应用进入后台、页面隐藏或动画被系统中断时，立即取消剩余视觉帧并显示同一已生成结果；恢复时默认进入完成态，不自动重播。
- 生成尚未完成时中断，恢复界面只显示“正在恢复上次结果…”并等待原会话；不得为了补动画创建新会话。
- 粒子只允许使用组件主题色的抽象点或短线，由确定性时间轴驱动，不代表随机结果，不进入语义树；达到／未达到不得采用庆祝或惩罚式粒子。

五态是 `AppGenerationStateView` 的展示状态，不是第二套领域状态机。映射固定如下：按压发生在 `ready` 内且取消不提交；生成对应 `generating`；揭示只可从已持久化的 `generated` 进入；完成对应 `completed`；减少动态是同一 generated/completed 数据的替代渲染路径。所有时长均为视觉上限，结果冻结不等待动画。

### 平台反馈与触觉合同

- 视觉、状态文字与读屏播报是必需反馈；触觉永远是附加反馈。静态导航、滚动、打开说明、查看历史和切换普通页面不强制震动。
- Android 使用平台语义 haptics，且“振动”可在设置中关闭：会话成功提交并冻结后可触发一次克制 `mediumImpact`，首个揭示或落位可触发一次 `selectionClick`，完整结果收束最多一次 `lightImpact`。塔罗不逐牌、D20 不逐骰、批量硬币不逐枚、扑克不逐张振动；六爻每爻最多一次落位反馈，第六爻完成可再有一次轻反馈。
- Web 只有在用户开启振动、运行环境暴露 vibration 能力、平台策略或授权允许、页面可见且当前操作由用户激活时才调用短振动；建议提交 `12 ms`、首次揭示 `8 ms`、完成 `10 ms`。任一条件不满足、调用被拒或抛错时捕获并 no-op，不显示随机失败，也不改变时间线。
- “减少动态效果”和“关闭振动”是独立设置。减少动态只移除旋转、位移、缩放、模糊和粒子；关闭振动或平台减少触觉偏好会跳过所有 haptic 调用。两者均不改变结果、焦点、读屏播报或完成条件。
- 应用进入后台、页面隐藏、路由离开或动画被中断时，取消尚未触发的视觉与触觉事件；恢复不补发旧触觉，不重播已完成动画。

### 塔罗揭示

- 每次生成阶段只确定本次新增牌及其方向；该张牌在牌背出现前即完成持久化，目标会话的部分结果可继续恢复。
- 逐张模式下，每个牌背是按钮，名称为“揭示过去位置的牌，第 1 张，共 3 张”；只能按位置顺序揭示。
- 一次揭示按位置顺序以 `80 ms` 错峰翻面；跳过后立即显示全部牌。
- 逆位通过牌面朝向、`逆位` 标签和读屏文本共同表达；不允许只旋转图片。

### 六爻投币

- 自动模式每次激活“投下一爻”只生成该爻一次；结果先写入当前会话，再播放三枚硬币翻转。
- 动画结束显示“三枚硬币：正、反、正；和值 8；少阴，静爻”，并把爻线从下向上加入。
- 当前爻生成后主按钮才恢复为“投下一爻”；第六爻完成后自动进入结果。
- 返回或中断恢复时，已完成爻保持不变；尚未开始的下一爻不预生成。

### D20 揭示

- 普通、优势、劣势和自定义模式都在一次规则执行中生成 `diceCount` 枚骰；动画不得按骰逐次请求随机值。
- 生成状态先显示冻结摘要，例如“4D20 · 保留最高 3 · +5 · DC 35”，再以最多 `640 ms` 的揭示序列显示全部骰。
- `1～6` 枚骰可同时入场；`7～20` 枚骰使用稳定网格和最多 `24 ms` 错峰，总时长仍不得超过 `640 ms`。
- 聚合完成后，每枚骰同时显示生成序号、点数和“保留／舍弃”文字；舍弃骰降低视觉强调但保持 AA 可读对比。
- 同值骰按较早生成顺序优先保留；动画顺序、视觉位置或排序不能改变该稳定选择，也不能把结果重新排序成看似不同的原始序列。
- DC 结论只在全部骰、保留集合、modifier 和 total 可见后进入完成态；达到或未达到不使用爆炸、老虎机、庆祝彩屑或惩罚性震动。

### 硬币揭示

- 单次结果先生成并持久化，再播放总长 `720 ms` 的真实感但非货币化圆片动作：`0～180 ms` 从 `translateY(0)` 抛起到 `-48 px`、`scale(1→0.94)`；`180～540 ms` 经过最高 `-64 px` 并绕水平线执行最多 `rotateX(720deg)`；`540～720 ms` 落回 `0 px`，允许一次 `2 px` 以内回弹并以冻结面朝向收束。图形无面额、铸币纹理或物理现金语义。
- 抛起、翻转和落定只改变 `CoinPrimitive` 的 transform；面值、原始二值与自定义标签从冻结 outcome 读取。跳过、减少动态或掉帧直接显示同一面值，不以最后动画角度推导结果。
- 批量一次生成完整序列，再以结果流逐项揭示；计数和比例从已生成序列读取。
- 批量大于 10 时不逐枚播放长动画，使用 `200 ms` 淡入并直接展示序列、计数和比例。

### 扑克牌揭示

- 生成态只显示中性牌背与“正在洗牌”，时长 `520 ms`；允许牌组整体 `translateX(-8→8→0 px)` 两次与 `rotateZ(-2→2→0deg)`，禁止牌面、点数、花色、大小王或抽取顺序提前出现。
- 揭示态按冻结 `sequence` 只从牌组抽出本次新增的一张牌，单张位移最多 `40 px`、`rotateZ` 最多 `4°`、`scale 0.96→1`；已有牌的动画进度固定为完成态，不因新牌进入而重播。
- 完成态按 sequence 保持视觉与 DOM 顺序，显示“剩余 N 张”；重新抽取只创建带 `parentSessionId` 的新会话，不从当前牌堆继续、不修改旧记录。
- 减少动态或动画关闭时不洗牌、不飞牌、不翻面，只在 `80 ms` 内按冻结顺序淡入；屏幕阅读器无需等待动画即可浏览全部有序结果。

### 减少动态效果

- 不旋转、不翻面、不连续缩放、不使用大范围位移。
- 生成完成后以 `80 ms` 透明度变化或立即显示结果；用户设置“关闭动画”时立即显示。
- 状态变化依赖数据完成事件，不依赖动画结束回调；“跳过动画”在无动画时不显示。
- 焦点位置和屏幕阅读器播报与普通模式一致。

## 结果

### 通用结构

1. 顶部实体舞台：状态胶囊、工具实体、主结果和必要的结构化摘要；`AppResultCard` 只能作为该舞台内部摘要。
2. 舞台下方的最小解释；有解释才渲染该区域。
3. 私人备注，独立可编辑并明确“仅保存在本机”。
4. 操作区：“再来一次”“调整配置”“复制文本”“分享”；“再来一次”与实体／主按钮复用同一命令。
5. 版本信息：“规则版本”“算法版本”；原始随机值和转换规则保留在会话、历史与分享载荷，不通过玩法页“查看过程”展示。

- “再来一次”复制规则配置，创建带 `parentSessionId` 的新草稿，不复制问题、备注或结果。
- “调整配置”创建新草稿并带入规则字段；问题和备注默认不带入，用户可单独选择。
- 结果内容缺失时保留原始结果，解释区写“解释内容暂不可用，结果本身未改变”。
- 分享或复制失败不关闭结果页、不改变当前结果。

### 解析位置与结果顺序

- 结果页的垂直顺序固定为“顶部实体舞台（状态／核心实体／结果摘要）→ 解析或解释 → 备注与操作”；不再出现独立结果卡或“查看过程”折叠区。
- 解析只消费已冻结的牌、方向、位置或规则结果；展开解析、切换折叠状态和滚动不触发随机或内容重算。
- 没有解析或解析字段缺失时，不显示空白解析卡；显示“解释内容暂不可用，结果本身未改变”，并保留复制、历史、恢复和文本分享。

### 塔罗结果

- 结果摘要先显示牌组范围：“78 张牌（含小阿卡纳）”或“22 张大阿尔卡那”；该字段与 `includeMinorArcana` 一起写入过程、历史和分享。
- 单牌卡显示位置、牌名、正位／逆位、3～5 个关键词、传统象征、当前方向差异、简短释义和 1～3 个反思问题；关闭逆位时不显示伪造或无关的逆位结论。
- 三牌在移动端按过去、现在、未来纵向排列；桌面端三列排列，DOM 与读屏顺序仍为过去、现在、未来。
- 三牌逐张解释绑定“过去／现在／未来”位置语义；组合提示只描述重复主题、张力和可能的观察方向，不输出必然事件、专业判断或确定性预测。
- 牌索引、抽取顺序、方向值、无放回规则、规则版本和内容包来源继续进入会话、历史和分享载荷；玩法页不再用“查看过程”展示这些字段。
- 结果页不显示来源区、许可状态或免责声明；内容包的来源与许可仅在发布审计层维护。解释字段缺失时保留牌名、方向、牌组范围和文字结果。
- 关闭小阿尔卡那时，解析只能引用 22 张大阿尔卡那内容；小阿尔卡那图像或解释许可缺失时保留牌名、方向、牌组范围和文字结果，图片分享禁用并回退文本。

### 六爻结果

- 首屏展示稳定卦 ID、卦名、上卦、下卦、六爻图和动爻标签；有动爻时并列或随后展示变卦，并用文字说明“哪些爻变化、如何翻转、变卦如何形成”。
- 无动爻时不显示空变卦卡，文案为“无动爻，本卦不变”。
- 六爻图视觉从上爻到初爻，旁边显示爻位；原始三枚硬币序列按初爻到上爻写入会话、历史与分享载荷，但不在结果舞台下方渲染独立过程列表。
- 原始三枚硬币、和值、阴阳、动静和变爻仍进入会话与分享载荷；玩法页不再渲染独立“形成过程”列表，避免结果舞台外再复制一份过程层。
- 解释按“卦象基础、动爻与变卦、结构关系”展开。传统原文和现代改写不进入首版 UI；原创结构简释只使用项目内容包，来源、作者、版本和许可记录放在内容包/审计文档中，不在玩法页展示。
- 首版不扩展到完整纳甲、六亲、世应、用神或自动断卦；玩法页不额外渲染免责声明或内容边界卡片。

### D20 结果

- 首屏依次显示模式标签、主数字“总值 N”、完整公式和可选 DC 状态；自定义示例为“自定义 · 4D20 · 保留最高 3”。
- “全部骰子”按生成顺序展示 `#1…#20`，每枚包含点数与“保留／舍弃”文字。即使同值也不合并、不按大小重排；高骰量在移动端换行，在 200% 字体下改为单列可读行。
- `sum` 下所有骰标记“保留”，公式为“全部骰求和 40 + 修正 5 = 45”；`keepHighest`／`keepLowest` 下公式为“保留 16 + 12 + 8 + 修正 5 = 41”。
- 顶部实体舞台的紧凑明细可显示 `diceCount`、`diceSides`、`aggregation`、适用时的 K、modifier 和 DC；稳定同值选择规则、规则版本和算法版本保留在会话、历史与分享载荷，不另建过程入口。
- 有 DC 时显示“达到 DC 35”或“未达到 DC 35”，并同时显示比较式“41 ≥ 35”或“34 < 35”；无 DC 时不出现成功／失败区域，改为“未设置 DC，仅显示检定总值。”。
- 普通、优势、劣势只在冻结字段仍完全匹配预设时显示预设名；否则显示“自定义”，不能根据结果内容猜测模式。
- 自然 1／20 只作为原始骰点展示，旁注“自然 1 或 20 不自动决定成败”。
- 屏幕阅读器先播报摘要，再提供“浏览全部 20 枚骰”列表；每项读作“第 4 枚，4 点，舍弃”，避免一次性朗读全部明细。

### 硬币结果

- 单次显示“正面”或“反面”，自定义标签作为主文案，原始面值作为辅助文案。
- 批量显示总次数、正反面计数和比例，再显示按产生顺序编号的序列。
- “率先达到”模式显示停止原因，例如“正面率先达到 3 次，共抛 4 次”。
- 比例以数字和文本表达，不只使用双色图表。

### 扑克牌结果

- 标题显示“抽取结果”，副标题逐字显示冻结配置，例如“标准牌组 · 不含大小王 · 抽取 3 张 · 无放回”。
- 牌按 sequence 和 DOM 顺序显示，固定示例为 `#1 黑桃 A`、`#2 红桃 10`、`#3 梅花 K`；牌 ID 分别为 `spades.a`、`hearts.10`、`clubs.k`，不得按花色、点数或布局重新排序。
- 结果摘要显示实际“已抽取 N 张”“剩余 M 张”，并保留本轮目标 `n`；抽完整 52/54 张时剩余为 `0`。每张牌同时提供花色、点数或大小王类型的读屏名称，不只用红黑颜色或图案。
- 操作为“重新抽取”“调整配置”“复制文本”“分享”；“重新抽取”复制配置并创建新的独立会话，旧会话、旧牌序和剩余数保持不可变。
- 历史详情和分享预览消费同一有序 card ID 列表、牌组配置与剩余数；默认分享不包含私人问题、备注、精确时间、本地 ID 或设备信息。
- 内容或牌面许可不足时，结果以稳定文字和抽象花色占位继续可读，图片分享禁用并回退“复制文本”；不得重新洗牌。

## 历史

### 历史列表

- 默认按完成时间倒序；卡片只显示工具、模式、主结果摘要和相对时间，不显示问题、备注、设备信息或本地 ID。
- 筛选依次为工具、收藏、时间范围；搜索仅查本地允许字段，输入旁标注“仅在本机搜索”。
- 移动端筛选使用底部页；桌面端在列表左侧或顶部常驻，结果总数通过礼貌区域播报。
- 同一父会话可折叠为组，但每条结果仍可独立打开、收藏和删除。
- 单条删除从更多菜单进入确认框；按工具删除和全部删除只在历史管理中出现，并明确数量与不可恢复影响。

### 历史详情

- 与结果页共享只读结果结构；增加收藏、删除和编辑私人备注。
- 原始结果、结构化输入、规则版本和算法版本不可编辑。
- 塔罗历史详情显示 `includeMinorArcana` 对应的 78/22 张牌组范围；开关值、牌组大小、牌序和方向不可编辑。
- 删除确认文案：“删除这条本地记录？删除后无法在此设备恢复。”按钮为“删除记录”和“取消”。
- 复用配置不默认带入问题、备注或原结果；新会话显示“来自历史配置”。

### 历史空状态

- 完全为空：“还没有历史记录。完成一次工具操作后，结果会保存在这里。”按钮“去选工具”。
- 筛选无结果：“没有符合条件的记录。”按钮“清除筛选”。
- 历史关闭：“历史保存已关闭。你仍可在结果页复制或分享当前结果。”按钮“前往设置”。
- 存储不可用：“当前无法读取本地历史。核心工具仍可使用临时会话。”按钮“重试读取”。

## 分享预览

- 分享从结果页或历史详情发起，先进入预览，不直接打开系统分享。
- 默认包含应用名、工具名、规则摘要、结果和规则版本。
- 塔罗分享摘要必须保留“含小阿卡纳 · 78 张”或“仅大阿尔卡那 · 22 张”的牌组范围；开关关闭时不得把小阿卡纳内容或图片混入载荷。
- 默认关闭“问题”“备注”“精确时间”；不提供本地 ID、设备信息、分析标识开关。

- 标题：“分享前预览”。
- 隐私说明：“只有下方预览中的内容会被分享。”
- 默认字段说明：“问题、备注和精确时间默认隐藏。”
- 链接声明：“此结果由分享者提供，未经服务器验证。”仅在未来离线载荷入口出现，v0.1.0 不提供公开链接。

## 输入与无障碍

### 触摸与鼠标

- 所有交互目标最小 `48 × 48 px`；相邻主要目标至少留 `8 px`。
- 不依赖悬停、长按、右键或拖拽完成核心流程；悬停只增加提示。
- 卡片点击区域与内部按钮分离，防止一次操作触发两条路径。
- 桌面支持鼠标滚轮和可见滚动条；横向内容在 200% 字体下改为纵向，不要求精确横向拖动。

### 键盘

- `Tab` 与 `Shift+Tab` 按视觉与 DOM 顺序移动；焦点不进入纯装饰图形。
- `Enter` 激活主按钮，`Space` 激活按钮、开关和选项；提交锁阻止按键重复生成。
- 简化玩法页的键盘顺序为核心实体（如有可操作牌面）、主操作、重置、高级选项、结果和解析；高级选项的 `aria-expanded` 状态与可见内容同步。
- 分段控件使用方向键切换，`Home/End` 到首尾；切换后立即更新可见说明。
- `Escape` 关闭最上层非破坏性模态；破坏性确认不会因误按 `Enter` 默认选择删除。
- 揭牌流程中焦点停在当前可揭示牌；揭示后移到下一张，全部完成后移到结果标题。
- 六爻自动模式完成一爻后焦点回到“投下一爻”；第六爻后移到结果标题。

### 焦点

- 焦点环至少 `2 px`，与相邻颜色保持可见对比，不使用仅变色的弱提示。
- 路由切换后焦点移动到页面主标题；验证失败移动到第一个错误字段。
- 打开模态时焦点限制在模态内；关闭后回到触发控件。
- 恢复结果时先播报恢复状态，再将焦点移动到结果标题；不抢夺用户正在操作的焦点。
- toast 不接收焦点；需要用户操作的错误必须使用横幅、内联错误或对话框。

### 屏幕阅读器

- 每页提供唯一主标题、`main` 地标和可理解的导航当前项。
- 图标按钮必须有动词和对象，例如“收藏这条 D20 结果”，不能只读“星形”。
- 塔罗牌语义示例：“过去位置，隐者，逆位，已揭示”；未揭示时不提前读出牌名。
- 塔罗配置语义示例：“使用小阿卡纳牌，开关，已开启，包含 22 张大阿尔卡那和 56 张小阿尔卡那，共 78 张”；关闭时读出“仅使用 22 张大阿尔卡那”。
- 塔罗简化页主操作读作“抽一张牌，按钮”；相邻重置读作“重置当前塔罗草稿，按钮”，不使用“重新抽取”混淆两者。
- 六爻语义示例：“第三爻，和值 9，老阳，动爻，将变为阴爻”。
- D20 摘要示例：“自定义检定，4 枚 20 面骰，保留最高 3 枚，修正加 5，总值 41，达到 DC 35”；全部骰通过后续列表逐枚浏览并播报保留状态。
- 硬币批量先播报摘要，再允许逐项浏览，避免一次读出 100 个结果。
- 扑克牌先播报“标准 52 张牌组，不含大小王，按顺序抽取 3 张，剩余 49 张”，再按 sequence 浏览“第 1 张，黑桃 A”等单项；不得通过布局视觉顺序改写播报顺序。
- 生成完成使用礼貌实时区域播报“结果已生成”；错误使用断言式播报，但不重复私人输入。
- 重置后播报“已重置当前配置，尚未生成结果”，不播报新的牌名或其他随机内容；恢复时先播报“已恢复上次结果”，再按冻结顺序读取结果和解析。

### 200% 字体

- 不使用固定高度承载文本；按钮和卡片允许增高，标签允许换行。
- 移动端保持单列；三牌、双卦、双骰和统计卡改为纵向排列。
- 粘性主操作区只保留一个主按钮，次操作移入正文，确保至少一半视口可见内容。
- 表格转为定义列表或可逐项阅读卡片；不得要求双向滚动才能完成核心任务。
- 360 × 800 且 200% 字体时，页面标题、当前配置、错误和主按钮均可通过纵向滚动到达。
- D20 模式改为纵向单选卡；骰面快捷项自动换行；每个步进器改为“标签与范围、数字输入、减／加按钮”三行结构，不压缩输入字符。
- D20 的 K 只在保留聚合下插入到聚合字段之后；显隐不得将当前焦点移到不可见控件。全部骰和公式按生成顺序纵向呈现，不使用横向滚动条。
- 扑克牌配置中的大小王开关、牌组摘要和抽取数量依次纵向排列；结果牌改为单列有序卡片，剩余数和主操作在横向滚动之外始终可达。
- 简化玩法页在 200% 字体下仍保持“核心实体、主操作、重置、高级选项、结果、解析”的纵向顺序；主操作和重置不能被折叠区或解析内容推到不可达区域。
- 塔罗小阿尔卡那开关的标签、78/22 张牌组摘要和错误说明允许换行；展开高级选项不会造成焦点跳到不可见字段。

### 对比、图形与反馈

- 正文、按钮、焦点、状态文本按 WCAG 2.2 AA 目标实现；最终对比度需要在实现稿中复测。
- 达到／未达到使用勾形／短横加文字；正位／逆位使用方向标签；动爻使用圆点加“动”字。
- 声音和振动永远是附加反馈；关闭或平台不支持时不影响状态理解。
- 装饰性牌背、骰子纹理和硬币高光从语义树隐藏。

## 响应式规格

### 360 × 800 小屏

- 页面边距 `16 px`，内容宽 `328 px`，单列，底栏固定。
- 顶部标题区可换行；次级操作进入更多菜单。
- 工具卡单列；D20 四种模式以两列单选卡呈现，200% 字体下改为纵向单选列表。
- D20 步进器占满内容宽；D4～D100 快捷骰面自动换行，自定义面数独占下一行；结果骰网格最少两列，200% 字体时改为单列列表。
- 三牌、六爻本卦／变卦、双骰、批量统计全部纵向排列。
- 主操作粘在底栏上方；键盘弹出时取消粘性并滚动当前字段到可见区域。
- 执行动画区高度在 `240～320 px`，不挤出进度文字和“跳过动画”。

### 平板

- `600～1023 px` 使用 `24 px` 页面边距，底部导航；内容最大宽 `880 px` 并居中。
- 首页工具卡两列；工具配置与只读规则摘要可两列，DOM 顺序先配置后摘要。
- 三牌可三列；本卦与变卦可双列；历史列表与筛选可上下或窄侧栏布局。
- 竖屏优先单列，横屏在每栏至少 `320 px` 时启用双列；旋转不重建会话。

### 1440 × 900 桌面

- 左侧栏 `240 px`，正文可用宽 `1200 px`；正文内边距 `32 px`，最大内容宽 `1120 px`。
- 首页五张工具卡使用三列加两列或自适应两至三列，保持阅读顺序“塔罗、六爻、D20、硬币、扑克牌”；最近结果位于工具卡下方，不建立第三层侧栏。
- 工具页采用左侧配置 `520 px`、右侧预览或规则摘要 `520 px`，间距 `24 px`；D20 配置右栏常驻显示结构化骰池摘要和示例公式，不预生成骰点。
- 桌面结果区保持“顶部实体舞台 → 下方解析”的阅读顺序；不得用 `7:5` 的独立主结果／过程分栏替代实体合并，三牌仍保持过去、现在、未来的 DOM 顺序。
- 历史使用 `280 px` 筛选栏加自适应列表；详情作为独立页，不用挤压式抽屉。
- 900 px 高度下标题、首个内容区和主操作无需页面横向滚动；正文允许纵向滚动。

### 断点切换规则

- `<600 px`：小屏单列。
- `600～1023 px`：平板，自适应一至两列，底部导航。
- `>=1024 px`：桌面侧栏与宽屏布局。
- 断点只改变布局，不改变页面、控件名称、配置值、会话 ID 或结果。
- 宽屏视觉重排使用 CSS／布局约束；DOM 与焦点顺序始终保持语义阅读顺序。

- 字段边界、键盘操作、读屏名称、焦点、200% 字体、减少动态、错误、离线、中断和恢复，以本文和 `tokens.json` 为准，并由组件与端到端测试验证。
- 平板连续重排和真实平台安全区由响应式约束与实现测试承担；静态 4K 展示板只证明选定视口的层级和状态意图。
- 精确颜色、字体、间距、圆角、阴影、触摸目标、动效时长和物理参数以设计系统和 `tokens.json` 为准，不从 PNG 测量。
- 生成图片中的任何额外文案、规则、数字、图标或资产都不是需求增量；与文档冲突时必须舍弃。

## 设计资产与许可边界

- 三张旧 built-in PNG 及其既有复核结论已被用户否决，并移入 [拒绝归档](design/archive/rejected-built-in/README.md)；它们只保留审计证据，不得作为布局、视觉、动效、提示词或实现依据。
- Round-1/2 六组历史证据与 Round-3 三组移动证据均保留原始路径、尺寸和 SHA；`3840 × 2160` 只表示后处理评审副本，不是模型原生 4K。尺寸、SHA、验收状态与需求映射见 [manifest](design/gpt-image-2-manifest.json)。
- 平台工具没有返回可机器核验的 model metadata；显式 CLI 因环境认证返回 HTTP 401 且没有图片产物，不得写成 CLI 成功或原生 4K。
- Round-3 `02/03/05` 的限定范围候选已 accepted，`04` 延续 accepted；Expanded Round-4 `01/07/08/09/10c/10d` 与 assembled 已 accepted，`10a/10b` 是 assembled 的 accepted tile 证据；旧 `01` 继续作为 D20 audit-only，Round-3 Web `06a/06b` 继续 scope-invalidated/audit-only。具体结论见 [设计稿评审](design/mockup-review.md)。
- 新提示词从更新后的需求、本文、设计系统和 tokens 独立建立，不从旧 PNG 的构图、文案、颜色采样或视觉元素派生。
- Flutter 与 Web 的行为以本文为准，颜色、字体、间距、圆角、材质、动效与断点以 `tokens.json` 和设计系统为准；未来图片与文档冲突时不得采用图片内容。
- 真实货币、赌场元素、未获明确再分发许可的传统或受版权保护的塔罗牌面、第三方标志、来源不明字体和生成错误文字均不得进入实现、运行时资源、商店截图、分享卡或其他发布资产；已通过逐张许可门禁的经典塔罗牌面只按 [Runtime visual asset & motion contract](design/runtime-visual-asset-motion-contract.md) 进入运行时。
- `includeMinorArcana` 只选择已登记的 22/78 张牌组，不替代许可审批；56 张小阿尔卡那的牌面、文字解释和分享素材必须逐项有来源、归属、哈希和再分发状态。许可未闭环时保留文字结果，隐藏或禁用受影响图片路径，不重新抽牌。
- 本批输出的许可状态为“内部设计参考，待 PM 最终许可复核”，`runtimeAsset=false`；G1 设计 PASS 不使其自动成为应用内置资源、发布内容或对外材料，本节不作法律保证。
- 用户新增的真实物体动效与经典牌面要求由 [Runtime visual asset & motion contract](design/runtime-visual-asset-motion-contract.md) 单独承接：它不把本批设计图升级为运行时资源，也不改变结果先持久化、动画只读 outcome、离线、无障碍、减少动态效果或触觉降级边界。经典牌面候选必须逐文件记录来源、SHA-256、归属和许可状态；许可未闭环时只允许文本结果和明确缺失降级。
- 塔罗牌面、六爻文本、字体、图标、音效和生成式图片需要分别审查；抽象示意图不代表对应内容已获授权。
