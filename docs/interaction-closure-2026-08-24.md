# Pocketools 当前交互收口合同

- **适用版本**：v0.1.1+2
- **生效日期**：2026-08-24
- **文档角色**：当前实现与回归测试的交互权威；早期设计稿中的旧导航、独立结果层、文本表达式输入和完成后禁用状态均不再作为验收依据。
- **平台**：Android、Web/PWA；所有平台共享同一规则模型、冻结结果和页面交互语义。

## 目标与边界

Pocketools 的六个玩法都围绕一个“真实随机实体”工作：牌堆、硬币、骰子、六爻的三枚铜钱或多重占卜的牌堆。实体负责承载状态、动画和结果，实体的可操作命中区负责触发唯一的随机动作，页面下方只放配置、解释和会话辅助操作。

本轮交互不重定义共享会话 envelope 或历史数据格式；现有塔罗与扑克抽取 codec 已支持目标数量未完成时的合法部分结果，并可恢复同一会话。本轮只把这项既有能力明确纳入交互合同，不新增另一套会话协议。重点收口以下行为：

- 首页与工具目录合并为一个“首页”入口；一级导航只保留首页、历史、设置。
- 结果与动画合并到同一个顶部实体舞台，不再渲染独立的“查看过程”或重复结果瓦片。
- 牌类使用同一套牌堆与横向追加基础组件；每次点击只追加一张新牌，新牌进入时才播放动画，已有牌不重播。
- D20 的 `aDb` 快速配置使用两个数字加减框；面数改变后草稿同步，骰子数量改变立即 reset 当前结果并在固定高度舞台内渲染新的骰池。
- D20、硬币和六爻通过共享实体交互合同表达“点击实体即执行”；六爻只有三枚铜钱可以投下一爻，卦象只打开信息。
- 所有玩法提供返回上一级路径；返回、刷新、后台恢复和动画中断不得生成第二个结果或丢失已冻结结果。
- 所有玩法遵守“实体动画先完成、最终详情后出现”：揭示中不提前展示新牌名、骰池总值、硬币面值、最新爻信息或融合解释；已有牌与历史结果保持静止。

## 共享实现合同

### 页面骨架

每个工具页面统一使用下列顺序：

1. `AppToolScaffold`：标题、规则摘要和返回按钮。
2. `AppEntityStateView`：唯一的核心舞台，包含状态、实体、动画和必要结果摘要。
3. 一个主操作按钮；完成后的语义由玩法决定。
4. 默认折叠的高级选项；高级选项可以在已有结果期间编辑，下一次动作才读取新配置。
5. 解释、会话操作或安全提示（若该玩法需要）。

共享组件的职责如下：

| 组件 | 职责 | 玩法层只提供 |
| :--- | :--- | :--- |
| `AppPhysicalAction` | 48 px 最小命中区、键盘激活、hover/splash、语义标签和统一焦点行为 | 实体 child、动作和语义文案 |
| `AppPhysicalDeck` | 牌堆的可点击包装，统一牌类命中合同 | 牌堆 child、抽牌动作 |
| `AppDeckResultFlow` | 牌堆在前、已抽牌在右侧，宽度不足时自动换行 | 牌堆和有序牌面列表 |
| `AppEntityStateView` | ready、pressed、generating、revealing、completed/reduced 的单一视觉平面 | 实体、结果摘要和状态文案 |
| `AppGenerationStateView` | `AppEntityStateView` 内唯一的状态胶囊，展示阶段、文案和读屏状态 | 阶段值与状态文案 |
| `AppStepper` | 数值范围、加减按钮、错误和语义 | 字段范围与 `onChanged` |
| `AppPhysicalStageSlot` | 为实体动画提供固定高度、可复用的物理舞台槽位 | 高度与实体 child |
| `AppRevealDetailsSlot` | 保留完成态布局但延后结果详情与语义 | 揭示完成条件与详情 child |

新增随机玩法应优先复用这些组件，不在页面内复制按钮、牌堆、结果列表或状态卡。全局按钮、间距、圆角、触摸尺寸和动效调整应能通过 design token 或共享组件单点生效。

### 冻结与动画

所有随机动作都遵守：

```text
校验配置 → 创建会话 ID → 取本次动作所需熵并生成 outcome → 保存冻结会话（牌类抽取可保存部分结果）→ 播放实体动画 → 展示完成态
```

动画只展示已冻结的 outcome，不重新随机。实体点击、主按钮和体感抛硬币（Android 可用时）必须进入同一 `primaryAction`，不能维护第二条随机路径。

- 正常动态：按压反馈、生成阶段、实体运动、揭示、完成收束和轻触觉反馈。
- 减少动态：保留状态变化、最终实体和文字结果，缩短或取消空间变换，不改变随机值。
- 生成/揭示期间暂时阻止重复提交；完成后恢复操作，不把按钮永久置灰。
- Web 与不支持平台对触觉、传感器能力静默降级，手动点击始终可用。

## 导航与返回

一级导航只有：

- 首页：工具卡片、最近结果和继续使用；工具目录不再拥有独立“工具”导航项。
- 历史：本地会话列表与详情。
- 设置：外观、反馈、隐私、历史和预设管理。

从首页、历史或设置打开工具时记录来源索引。工具页的系统返回、浏览器后退和页面顶部返回按钮统一回到来源页；从历史详情重放打开的工具返回历史，从设置预设打开的工具返回设置。工具页返回不清空已保存会话；未提交草稿只保留在当前页面生命周期内。

模态解释页优先消费返回操作，关闭后焦点回到触发实体。浏览器刷新或应用恢复时，已保存结果恢复为同一会话，不重新取熵。

## 塔罗与扑克牌：共享牌堆交互

### 共同规则

塔罗和扑克牌都使用 `AppPhysicalDeck` + `AppDeckResultFlow`。牌堆始终保留在结果流的第一个位置，已抽牌从其右侧按抽取顺序追加；当前行放不下时自动进入下一行，不通过网格排序改变顺序。

牌堆是抽牌入口，点击牌堆严格只新增一张牌，不重新播放已有牌的动画。`animateIndex` 只指向本次新增牌；已存在牌的动画进度固定为完成态。多牌配置的 `n` 只表示本轮目标数量，不表示一次性批量动作；部分抽取会话由既有 codec 支持恢复。

### 塔罗

- 初始显示有高度的牌堆和牌背，不显示空结果卡。
- 点击牌堆抽出一张牌，牌从右侧进入并绕 Y 轴翻面；牌面使用已登记的经典塔罗运行时牌面，结果先冻结后翻牌。
- 再次点击牌堆继续抽下一张；单牌模式每次只增加一张，不改写已有牌。
- 点击任意已抽出的牌，打开 `TarotInterpretationSheet` 底部弹层；释义不嵌在牌下方，不撑大主体页面。
- 弹层至少展示牌名、正逆位、关键词、象征、简释和反思提示；内容仅作文化学习、娱乐和自我反思，不提供专业判断。
- 高级选项可切换是否使用小阿卡纳牌：开启为 78 张，关闭为 22 张；开关和牌组摘要在下一次抽取时生效。
- 完成后主按钮继续创建新抽取会话；塔罗保留显式“重置”用于清空当前草稿/结果，不删除历史。

### 扑克牌

- 初始显示带厚度的牌堆；点击牌堆抽一张，牌面进入右侧并翻面。
- 支持是否包含大小王，以及本轮目标数量 `n`；每次点击只抽一张，达到 `n` 后继续点击会创建下一张关联抽取会话。高级配置变化不影响当前已展示牌，下一次抽牌使用新配置。
- 结果显示序号、可见牌面和文字牌名（例如“梅花 2”），并保留剩余牌数。
- 完成目标前继续点击牌堆只追加下一张；达到目标后继续点击仍只追加一张新牌；已存在牌保持静止，避免整组闪烁或重复洗牌。
- 扑克与塔罗不复制另一套牌堆实现；差异只在牌模型、牌面组件、解释行为和配置字段。

## D20 鉴定

- 顶部实体舞台按 `diceCount` 展示对应数量的可点击骰子；每一枚骰子的命中区都进入同一个掷骰动作。
- 顶部 `快速配置 · aDb` 由“骰子数 a”和“骰面 b”两个只读数值框组成，每个框只有减号和加号；不提供文本输入框。
- a 或 b 每变化一次，下面的实体骰子数量/标签和下一次配置摘要立即同步；范围为骰子数 `1～20`、骰面 `2～1000`。
- 高级选项仍提供可编辑的详细骰池、聚合、K、修正值和 DC；用户可以在完成动画期间编辑，下一次掷骰读取新配置。
- 掷骰后结果数值、保留/舍弃语义、总值、公式和 DC 摘要与实体骰子保持在同一舞台，不创建旧式独立 `DiceRollTile` 结果层。
- 当骰面达到或超过 20 时，使用同一可识别的实体骰子图像，并把实际点数作为叠加数字；不伪装成用户能数清的高面数实体图。
- 完成后主按钮和骰子均可执行“重置当前显示并重新掷骰”，页面不显示独立重置按钮。

## 抛硬币与六爻

### 抛硬币

- 初始显示一枚有厚度的实体硬币，点击硬币或主按钮抛掷。
- 硬币绕水平的 X 轴翻转；动画包含抬起、翻面、边缘可见、下落、阴影落地和收束。边缘素材在进入侧面状态时转为水平铜钱边缘，不能出现竖直条带穿过正面。
- 结果和动画留在同一实体舞台；批量结果在实体下方显示计数和顺序摘要，但不复制为过程层。
- 完成后主按钮显示“再抛一次”，原子执行 reset + reroll，不显示独立重置按钮。
- Android 体感入口只触发同一个主操作，不参与面值推导；Web、非 Android、权限/传感器不可用时保留点击硬币和主按钮。

### 六爻

- 自动模式中，三枚实体铜钱位于卦象上方；初始和每一爻确认时只有铜钱命中区可触发下一爻。
- 卦象和已确认爻线是信息区：点击卦象打开完整卦象含义；尚未完成时打开“目前各爻信息”，不投币、不消耗随机值。
- 六次操作从初爻到上爻生成；每一爻的三枚铜钱、和值、阴阳、动静和变卦映射进入冻结会话。
- 页面不展示“内容边界”、来源、许可或形成过程卡。必要解释保留在卦象/爻结构的简释中；来源、作者、版本和许可仅保留在内容包与 `docs` 审计文档。
- 手工模式继续支持录入和值/三枚铜钱；自动与手工共用同一卦象展示和返回恢复逻辑。
- 六爻完成前保留草稿重置；完成后主操作创建新的起卦草稿，不改变旧会话。

## 验收清单

- [ ] 首页只显示首页、历史、设置三个一级导航，首页包含六个工具入口。
- [ ] 六个玩法的实体舞台没有独立“查看过程”或重复结果对象。
- [ ] 塔罗与扑克使用共享牌堆流；塔罗牌面释义通过弹层打开；扑克只动画新增牌。
- [ ] D20 aDb 两个加减框实时影响实体骰子，且快速区没有 `TextField`。
- [ ] D20 高面数使用统一实体图和实际点数叠加；结果语义仍在同一物理舞台。
- [ ] 硬币水平轴翻转且边缘方向正确；六爻铜钱在卦象上方，卦象点击不投币。
- [ ] 完成后按玩法恢复操作；高级选项不因结果被禁用。
- [ ] 系统返回、浏览器后退和页面返回按钮都回到上一级，恢复不重随机。
- [ ] `make check-format`、`make analyze`、`make test`、`make build-web` 和 Android release 构建均有实际执行证据。
