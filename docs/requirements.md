- **需求变更规则**：FR、NFR、REL 编号一经发布不复用；新增需求使用新编号，删除或降级需求必须在变更记录中说明原因、影响和替代验收条件。
- **开发准入**：关键页面交互文档和符合 gpt-image-2、4K/high 评审门禁的设计稿已完成并通过『docs/project-plan.md』中的 G1；模型原生分辨率和底层版本只按平台实际返回信息记录，不作推定。
- **当前增量**：多重占卜不改写本 v0.1.0 冻结需求 ID；其塔罗／周易融合规则、解释边界、交互和验收条件由[多重占卜设计与实现说明](multi-divination-design.md)单独维护，并通过模块级测试追踪。

## TL;DR

- **目标**：提供塔罗牌、六爻、D20 检定、抛硬币和扑克牌五类可信、克制、离线可用的随机工具。
- **塔罗范围增量**：塔罗支持 `includeMinorArcana` 开关，默认 `true`，开启时使用 78 张牌，关闭时仅使用 22 张大阿尔卡那；开关文案、结果追溯和内容许可边界固定见 FR-053。
- **页面结构增量**：五类玩法页默认只展示顶部核心实体、一个主操作和按玩法显示的重置；高级配置默认折叠，解析位于结果下方，具体行为固定见 FR-054 与 [交互收口合同](interaction-closure-2026-08-24.md)。
- **D20 范围增量**：D20 除普通、优势、劣势快捷预设外，支持 1～20 枚骰子、2～1000 面和 sum/keepHighest/keepLowest 聚合的自定义骰池。
- **扑克范围增量**：`includeJokers` 默认 `false`，使用标准 52 张牌；用户显式开启后加入 2 张大小王，使用 54 张牌；支持无放回抽取 n 张，抽取顺序、历史和分享结果均可追溯。
- **解释与反馈增量**：塔罗和六爻提供有来源边界的必要解释；五类随机流程提供按压、生成、揭示、完成及减少动态效果状态，并按平台能力提供可关闭的触觉反馈。
- **工程交付增量**：根目录 Makefile 提供统一命令入口；工具通过 `ToolModule` 注册、共享会话协议、随机核心、历史分享集成、UI 组件和 design tokens 扩展。
- **核心验收**：五类工具都能在 Android 与 Web 完成核心流程，结果可解释、可记录、可复用和可脱敏分享；新增工具不要求大改应用 shell。
- **需求追踪**：功能需求使用 FR-加三位数字，非功能需求使用 NFR-加三位数字，发布与治理需求使用 REL-加三位数字。
- **隐私边界**：MVP 不要求账号，不上传问题、备注、结果或自定义标签；分享前必须预览，默认隐藏私人字段。
- **内容边界**：塔罗和六爻只提供文化、娱乐和自我反思提示；不提供医疗、法律、财务、自伤或博彩结论。
- **随机边界**：默认使用平台安全随机源和无偏抽样；结果页可以解释算法，但不宣称本地结果具备第三方防作弊证明。
- **发布决策**：本地候选冻结为 Android minSdk 24 的 debug 构建与 Edge 151 的真实 Web/PWA 验收；v0.1.0 只交付 zh-Hans，不设公共渠道。Git 身份、Android 设备、完整浏览器矩阵、release signing、英文与性能矩阵留待后续门禁。

## 背景与问题

Pocketools 将需要随机过程的轻量活动放入一个统一工具箱。现有产品常见以下问题：

- 不同工具的配置、随机、结果和历史体验割裂。
- 简单随机操作容易被登录、广告或网络请求打断。
- 结果只展示最终数值，用户无法复查原始抽取和规则转换。
- 占卜内容容易被表述为确定性预测，给用户造成不当权威感。
- Android 与 Web 的离线能力、本地历史、分享脱敏和无障碍行为不一致。

本需求文档把已确认的产品范围转换成可以逐条实现和验收的契约。产品概览、完整方案背景和候选架构见『docs/product-design.md』；角色边界、阶段门禁和交付流程见『docs/project-plan.md』。

## 目标与非目标

### 产品目标

- 在 Android 与 Web/PWA 上提供一致的五类随机工具。
- 让常用的单次随机操作在首页进入后不超过 3 次主要交互完成。
- 让每次已完成会话都能说明输入、原始随机结果、规则版本和最终结果。
- 让用户在断网时完成核心流程，并在本地管理历史和预设。
- 让用户在分享前控制公开字段，默认保护问题、备注和设备信息。
- 为后续随机数、抽签、转盘和通用骰子等工具保留可扩展的规则边界。

### 非目标

- 不提供真人占卜、社区、社交匹配、云端排行榜或多人房间。
- 不提供账号、跨设备同步和依赖后端的核心随机能力。
- 不提供医疗、法律、财务、考试、彩票或自伤场景的确定性决策。
- 不提供真钱下注、奖池、兑奖、可交易积分、现实奖品或博彩导流。
- 不在 v0.1.0 实现六爻纳甲、六亲、世应、旬空、神煞和完整自动断卦。
- 不在 v0.1.0 实现完整桌面角色卡、战斗管理或 D&D 全规则百科。
- 不承诺本地结果能够证明设备、构建包或用户本人没有重抽或篡改。

## 用户与核心流程

### 目标用户

| 用户类型 | 主要任务 | 成功标准 |
| :------- | :------- | :------- |
| 轻量决策者 | 快速抛硬币或完成一次 D20 | 不配置账号即可看到清晰结果 |
| 塔罗兴趣用户 | 抽单牌或三牌阵并保存反思 | 能看牌面、位置、方向和克制释义 |
| 六爻学习者 | 自动投币或手工录入六爻 | 能确认每一爻原始输入、本卦、动爻和变卦 |
| 桌游玩家与主持人 | 快捷 D20 或自定义骰池检定 | 能配置数量、面数、聚合、修正值和 DC，并追溯所有原始骰 |
| 卡牌工具用户 | 从标准扑克牌组无放回抽取指定数量 | 能选择是否包含大小王，并复查抽取顺序和剩余牌数 |
| 结果分享者 | 导出可读、脱敏的结果 | 发送前能预览并关闭私人字段 |

### 统一会话状态

- 草稿：允许编辑意图、备注和规则配置，尚未消耗随机值。
- 就绪：输入通过校验，等待用户明确开始。
- 生成：输入和规则版本冻结，只允许一次随机执行。
- 揭示：展示已生成的结果，动画不能重新请求随机值。
- 已完成：结果只读，可在顶部实体舞台查看结论，在历史/分享载荷中追溯原始序列、规则和版本，并保存备注、复用配置、复制和分享；页面不额外渲染“查看过程”入口。
- 临时会话：本地存储不可用时允许完成，但退出后不保证保留历史。

每个工具都必须遵守“结果先生成并持久化，再播放动画”的顺序。动画中退出、刷新或重复点击不得生成第二个结果。

## 优先级与验收约定

### 优先级

- **P0**：首版核心能力或安全、隐私、发布阻塞项；未通过时不得交付 v0.1.0。
- **P1**：首版完整体验的重要能力；若延期，必须由项目经理记录影响和替代方案。
- **P2**：增强能力；可以在首版后实现，不得阻塞核心流程。

### 验收表达

- 每条需求的“验收条件”是最小可核对结果，不等同于完整测试用例。
- 测试人员需要将验收条件映射到单元、组件、端到端、无障碍、兼容性或人工检查证据。
- 未执行的验证必须标记为“未验证”，不得写成通过。
- 规则数据、内容数据、视觉资产和第三方依赖都必须能追溯到版本、来源和许可状态。

### Makefile 命令契约

本节定义开发交付接口，不声明当前仓库已经实现或验证任何命令配方。开发人员应在 G1 放行后依据实际工具链提供薄封装，CI 只能调用同一组目标，不复制另一套隐藏命令。

| 目标 | 交付语义 |
| :--- | :------- |
| `help` | 默认目标；列出可用目标、用途、前置条件和不会执行的破坏性动作，不安装或构建项目。 |
| `bootstrap` | 检查并准备项目明确声明的开发依赖；离线、版本不匹配或工具缺失时给出可操作错误，不静默修改系统级工具链。 |
| `format` | 调用项目实际格式化器处理受支持源文件，并以本地与 CI 一致的规则结束。 |
| `analyze` | 调用项目实际静态分析和架构检查入口，不把警告静默降级为成功。 |
| `test` | 执行项目定义的默认测试集合，并明确包含和排除的测试层级。 |
| `test-unit` | 执行规则、随机核心、会话与其他纯单元测试。 |
| `test-widget` | 执行共享组件、工具页面和交互状态的组件测试。 |
| `build-web` | 产生可核对的 Web 发布候选构建；缺少平台工具时明确失败。 |
| `build-android` | 产生项目定义的 Android 发布候选构建；签名或渠道前置条件不得被伪造为已具备。 |
| `build-android-release` | 产生经过 Flutter/Gradle 优化的 Android release 构建候选；必须单独记录实际签名归属，不得把 debug 证书伪装成商店签名。 |
| `verify` | 聚合当前版本声明的格式、分析、架构、测试和必要构建门禁，作为本地与 CI 的统一验证入口。 |
| `clean` | 只清理项目明确拥有且可重建的产物；不得删除本地历史、用户输入、凭据、工作区外路径或宽泛目录。 |

## 业务规则与数据契约

### 随机记录

每次已完成会话至少保存以下字段：

- 工具 ID、schemaVersion、规则版本和算法版本。
- 用户确认后的结构化输入。
- 塔罗结构化输入中的 `includeMinorArcana`、牌组范围和牌组大小。
- 原始离散结果，例如牌索引、三枚硬币、每枚骰点或二值面值。
- 从原始结果到展示结果的转换过程。
- 内容包 ID、版本、语言和许可归属引用（适用时）。
- 创建时间、完成时间和 parentSessionId。

不得保存可用于倒推出其他会话的全局随机内部状态。结果展示、历史、复制和分享必须消费同一份已生成结果。

### 塔罗规则

- `includeMinorArcana` 默认 `true`；开启时牌组为 78 张，关闭时牌组只包含 22 张大阿尔卡那。
- 开关文案为“使用小阿卡纳牌”；关闭后的摘要必须明确写“仅使用 22 张大阿尔卡那”。
- 单牌抽取 1 张，三牌阵抽取 3 张；无论牌组范围如何，同一会话内均无放回。
- 同一会话内无放回；三牌阵位置固定为过去、现在、未来。
- 逆位开关的默认值由设计门禁冻结，方向随机必须与抽牌随机分开记录。
- 牌面内容只提供关键词、简释和反思问题；内容来源和许可必须可追溯。未审核的小阿尔卡那内容或牌面不进入发布包，结果可用时使用文字降级且不得重抽。

### 六爻规则

- 正面为 3，反面为 2；三枚之和为 6、7、8、9。
- 6 为老阴动，变阳；7 为少阳静；8 为少阴静；9 为老阳动，变阴。
- 内部数组索引 0 为初爻，索引 5 为上爻；展示从上爻到初爻时必须保留数据映射。
- v0.1.0 不推导纳甲、六亲、世应、旬空、神煞或确定性吉凶。

### D20 规则

- diceCount 为 1～20；diceSides 为 2～1000，并提供 D4、D6、D8、D10、D12、D20、D100 快捷值。
- aggregation 支持 sum、keepHighest K、keepLowest K；K 为 1～diceCount。
- 普通、优势、劣势分别是 1d20/sum、2d20/keepHighest 1、2d20/keepLowest 1 的快捷预设。
- 修改快捷预设的数量、面数或保留规则后，模式显示“自定义”，但不丢失配置来源。
- total 为保留骰求和加 modifier，再与可选 DC 比较；自然 1/20 默认不自动成功或失败。
- 数量、面数、聚合、K、modifier 和 DC 在开始前统一校验并冻结，生成后不能改变当前结果。
- 每一枚原始骰都保留生成顺序和保留/舍弃状态；表达式只作为同一结构化骰池模型的输入方式。

### 硬币规则

- 单次模式生成一个二值结果；批量模式按用户指定次数逐次生成。
- 默认次数为 3、5、10，可自定义 1～100。
- 自定义标签只改变展示，原始面值必须保留。
- 率先达到 N 次模式属于可选增强，不得改变普通批量模式的次数语义。

### 扑克牌规则

- 基础牌组由黑桃、红桃、方块、梅花四种花色与 A、2～10、J、Q、K 十三种点数组合，共 52 张稳定且唯一的牌 ID。
- `includeJokers` 默认 `false`；未显式开启时牌组为 52 张，用户显式开启后加入 2 张具有不同稳定 ID 的大小王并形成 54 张牌组。
- n 为 1～当前牌组大小；配置、牌组版本和抽取结果在开始后冻结。
- 一次会话使用统一无偏随机核心完成洗牌并按顺序无放回抽取；结果记录每张牌的 sequence、牌 ID、花色、点数或大小王类型。
- 完成会话不可修改；重新抽取创建新会话，不复用旧会话的随机结果。

### 解释内容规则

- 塔罗解释逐牌包含关键词、传统象征、正逆位差异（适用时）和反思问题；来源与许可只作为内容包和发布审计元数据维护。
- 三牌解释分别绑定过去、现在、未来位置，并可提示牌与牌之间的主题联系；不得把组合提示写成必然事件或专业结论。
- 六爻解释包含卦名、上下卦、卦象基础、动爻和变卦的结构关系；内容包和发布审计记录保留来源与许可状态，玩法页不展示对应入口。
- 六爻首版不扩展到完整纳甲断卦；医疗、法律、财务、自伤等高风险主题只显示通用安全提示。

### 反馈与恢复规则

- 五类玩法页的默认顺序为“核心实体、单一主操作、相邻重置、高级选项、结果、解析”；高级选项展开或收起不生成随机值。
- 塔罗默认进入单牌模式，主按钮为“抽一张牌”；每次激活只创建一张牌的抽取结果，重置只清理当前草稿或创建新草稿。
- 五个工具的随机值与结构化结果必须先冻结并进入可恢复会话，再开始任何动画、声音或触觉反馈。
- 五态为按压、生成、揭示、完成、减少动态效果；硬币至少表达抛起、翻转、落定，扑克牌至少表达洗牌、抽牌。
- Android 触觉按阶段使用且可关闭；Web vibration 仅在能力检测和用户设置允许时调用，不支持时静默降级。
- 应用进入后台、页面隐藏或动画中断后恢复同一结果；减少动态效果和关闭振动不改变流程、结果或无障碍播报。
- 静态导航使用视觉、焦点或状态反馈即可，不要求逐次震动；禁止用连续或惩罚性反馈制造骚扰。

## 隐私与本地内容

### 用户数据

- 不要求手机号、邮箱、联系人、定位、相机、麦克风或后台运行权限。
- 问题、备注、自定义标签、结果和分享载荷默认只在本地处理。
- 默认分享不包含问题、备注、精确时间、本地 ID、设备信息和分析标识。
- 用户主动勾选字段后才允许进入分享预览；预览取消不影响原会话。

### 内容表达

- 塔罗和六爻结果只按结构化内容字段展示，不根据用户输入生成确定性或专业结论。
- 用户输入只在本地处理，不上传原文，不把输入内容改写为额外免责声明或内容边界卡片。
- 产品不接入真钱、奖品、下注、可交易积分或博彩导流。
- D20 使用通用玩法术语；任何第三方规则文本、商标、插画或字体必须单独完成许可审核。
- 扑克牌只使用原创或许可明确的抽象标准花色符号，不使用赌场桌面、筹码、下注、赔率、现金或博彩导流语义。
